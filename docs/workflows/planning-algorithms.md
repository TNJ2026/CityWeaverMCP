# 规划算法与边界

## 并发与性能测量

同一 `request_id` 的并发建筑规划共享一个执行中的 Promise；参数不同立即返回 `IDEMPOTENCY_CONFLICT`。取得施工锁后再次检查已完成和不确定事务记录，防止排队期间记录变化导致重复预览。内部批量规划不等待占用同一施工锁的外部请求，避免互相等待。

建筑规划返回 `performance`：`elapsed_ms` 为整个请求耗时，`stages_ms` 包括发现、排队、候选生成与过滤、分析、评分、预览，`queries` 记录每个桥接工具的调用次数、失败次数和累计耗时，`counters` 包含候选与预览次数。查询耗时包含通信与游戏执行，不能单独解释为游戏算法耗时；并行查询的累计时间可能超过请求墙钟时间。阶段和查询统计是不同视角，不能相加。错误响应也携带已收集的统计；幂等命中保持原计划的统计。

从 `mcp` 目录运行 `npm run bench:planning -- 7` 可执行固定随机种子的离线基准。包含三个规模的索引与线性扫描对照、街区搜索、管线绕障，以及批量和旧版逐点分析的模拟工作流。每项预热两次，再输出中位数、P95、场景规模与校验结果；参数为重复次数（1–100）。脚本不连接游戏、不修改城市。可用 `node mcp/benchmark-planning.mjs 7 > artifacts/planning-benchmark.json` 保存报告。

基准中的查询次数和场景结果可复现，耗时随机器和负载变化；真实城市仍需结合返回的 `performance` 评估。小数据量下建索引不一定更快，不依据单次耗时添加优化阈值。

## 搜索与分析

建筑选址采用沿路多点采样、空间分区候选保留、旋转矩形碰撞筛选和分类贪婪评分。服务覆盖批量读取一次城市快照，并建立随本次请求销毁的空间索引；施工后重新查询。参数和预留占地用法见 [建筑指南](../guides/buildings/BUILDING-GUIDE.md)。建筑顺序仍按输入顺序执行，不会自动改变施工依赖关系。

教育与交通分析也支持 `positions`（1–32 个坐标，与单点或实体中心选择器互斥），返回按输入顺序排列的 `items` 和 `snapshot_reads=1`。教育先按学生当前所在建筑和教育等级聚合人数，再建立空间索引；交通先确定候选范围内的站点，再统一遍历线路汇总站点候车人数，避免每个站点重复扫描全部线路。所有索引仅存在于本次请求，下一次规划重新读取。

`analyze_transport_catchment.nearby_waiting_passengers` 统计范围内全部匹配站点，独立于 `stop_limit`；新增 `listed_waiting_passengers` 表示实际返回明细的候车人数。旧版总数只累计返回的明细，若调用方依赖旧语义，应改读该字段。教育的容量总计仍包括范围内所有学校，分类评分按目标学校的教育等级过滤。旧模组不支持批量查询时回退逐点分析，并按城市会话记录能力，避免每栋都重试不支持的批量接口。

街区选址为建筑、水域、地形和道路采样点建立空间索引。道路曲线使用实际 Bezier 曲线采样，不再把控制点当作道路上的点；建筑包围盒考虑旋转。细网格超过 4096 个位置时，以四倍步长初筛，将搜索范围分成 4×4 个区域，各保留一个最优种子并在周围细化；细化后仍没有无冲突候选时回退到细网格。返回 `search_strategy`、`evaluated_candidates` 和 `fallback_fine_search`，便于检查搜索量。地形样本缺失或无效时返回 `terrain_known=false`、空坡度/高差，并增加未知数据惩罚，不当作平地。粗到细搜索是近似搜索，不保证全局最优。

管线 `routing=auto` 先尝试去重后的直线和两种 L 形路径。全部被原生预览拒绝后，读取覆盖最大绕行范围的建筑快照并尝试 A*；快照截断或不可用时不使用不完整障碍数据。绕行边界依次尝试 128、256、512 米，默认 16 米网格，长距离按格点上限自动加粗，失败后在上限内尝试半步长细化，最多六次搜索，每次最多 16000 个格点。代价包含长度与转弯，状态保留方向；同一条边的通行结果在本次搜索内缓存。每段与障碍包围盒做整段相交检测，简化后最多 16 个路径点，再交给原生预览。空间索引按查询范围选择遍历格子或已有桶，并支持首个命中即返回。

建筑预览超时、城市会话改变或结果未知时立即停止候选回退；即使 `continue_on_error=true`，批量施工与计划绑定也停止。错误包含 `recovery_required`、原 `operation_id`（若已取得）及预览 `request_id`；同一规划请求在当前 MCP 进程内保留错误，重复调用不会另开预览。检查原事务并处理恢复后，才用新的规划请求继续。

预留占地过滤后不足以满足候选预算时，工作流逐步扩充候选数，最高 32 个，保持原搜索范围。`reserved_size_m` 随计划持久化升级后的预留尺寸，后续绑定和规划碰撞校验统一读取，基础 `size_m` 保留建筑本身尺寸。

该管线绕障是平面建筑几何代理，不模拟地形、地下深度或真实网络容量；有些地下管道本来可以穿越地面建筑，因此仅作简单路径失败后的补充。`direct` 和 `orthogonal` 不启用 A*。预览超时或结果未知时停止，避免用新请求重复执行不确定事务。

道路原有 A* 保持不变，建筑障碍查询改为空间索引，降低逐格线性扫描成本。以上优化均保留现有原生预览、费用上限和永久实体回读流程。

验证覆盖负坐标空间索引、跨格大占地去重、旋转碰撞、真实曲线采样、批量查询刷新、规划占地传递、复杂绕障与搜索上限。单元测试中的查询次数和搜索量不等于真实城市中的耗时；游戏运行性能和建造成效仍需实测。


## 查询与搜索复用

- 自适应管线寻路在同一次调用内复用障碍包围盒和空间索引；不同网格的边通行缓存仍独立，避免混用网格编号。
- 道路最近点搜索先按 X 坐标排序，通过坐标距离下界剪枝；最终仍使用欧氏距离，并按原候选顺序处理等距点，保持评分与连接点选择一致。基准包含排序成本及穷举结果校验。
- 每个选址候选的地形统计合并为一次遍历，保留边界包含、未知数据以及负高程的原有处理。
- 同一城市会话、类别和预制件的进行中发现查询共享 Promise，成功后使用现有缓存，失败后删除进行中记录以允许重试。共享查询的实际调用耗时归属发起者，其他等待者的 discovery 阶段仍包含等待时间。
