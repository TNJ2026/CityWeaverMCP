# 从零建城：小规模启动，按承载能力扩张

先读 [策略选择与评估](development-strategies.md)。这里默认普通经营、自然入住、有限资金；用户另有设定时调整。阶段按城市状态推进，不按固定人口解锁清单机械盖楼。

## 1. 勘察和预算

选择靠近外部道路、容易供水排污、可低成本铺路的起点。读地形、水体/地下水、风与污染、资源地、已购地图边界；保留未来主干道、货运和公共设施走廊。具体排污位置核实水流/污染传播，不凭屏幕朝向判“下游”；地下水供给核对补给与污染。

玩家攻略强调先看地形、风、水源和资源再落路网；可采用顺应地形的几个小网格，避免为了整齐先大幅改造全图。[玩家经验摘要](https://glasp.co/youtube/r6ckYp1YPcI)。饮用水必须避开污染，地下水并非无限供应。[官方服务机制](https://www.paradoxinteractive.com/games/cities-skylines-ii/features/city-services-districts-policies)。

列最小启动包：接入道路、供电连接或小型发电、清水、污水出口/处理、首批住宅与岗位、必要服务及储备。比较实际建设和维护，不按“最贵设施效率最高”购买。地块只购买近期项目所需；远期蓝图可以留白，不等于立即买地铺路。

### 开工基线

任何永久施工前先建立一次可复核的基线。基线不是截图或主观印象，应保存查询时间、城市会话和下列原始结果；换存档、游戏重启或地图发生大规模变化后重新采集。

| 基线领域 | 至少记录 | 推荐查询 |
| --- | --- | --- |
| 会话与能力 | 城市是否已加载、会话标识、暂停状态、可用工具和限制 | `get_game_status`、`get_query_capabilities` |
| 经营条件 | 城市主题、左右行驶、无限资金/全部解锁、当前资金、收支差额、贷款与信用额度 | `get_city_configuration`、`get_city_economy` |
| 人口与进度 | 人口、健康、幸福度、当前里程碑、发展点、地图许可 | `get_city_summary`、`get_city_progression` |
| 土地与外部条件 | 已购地图格、可建设范围、外部连接、海平面、地形、水体/地下水、风向、污染和自然资源 | `get_map_overview`、`list_map_tiles`、`analyze_map_tile_features`、`get_climate_state`，并按候选点补充地形和污染查询 |
| 可建设内容 | 已解锁道路、分区、管网、建筑与城市服务的精确 prefab 名称、宽度、占地、容量和前置条件 | `list_road_prefabs`、`list_zone_types`、`list_utility_network_prefabs`、`list_building_prefabs`、`list_city_service_prefabs` |
| 启动预算 | 各项预计建造费、持续维护费、不可动用储备、允许的本阶段最高成本 | 各领域 preview 的真实报价，加上 `get_city_economy` 当前结果 |

基线完成后确定一个“最后已知良好状态”：记录原模拟速度、当前永久对象、预算和关键指标；大型阶段开始前在游戏内建立命名存档点。MCP 跨道路、管网、建筑和分区的组合施工不是单个原子事务，存档点用于处理无法通过逐项修复恢复的情况，不代表可以跳过 preview 和永久对象回读。

**通过条件**：候选起点位于可建设且已购土地内，外部道路与生命线均存在可行接入方案，精确 prefab 已发现，启动包的建造费、维护费和储备可承担。任一项未知时保持在勘察阶段，不进入永久施工。

## 禁止条例（硬约束）

以下行为会直接破坏授权边界、永久拓扑、环境安全或阶段验收。任一项命中时必须停止对应施工并修正方案，不能仅记录为普通警告后继续：

### 授权与数据

- 禁止在未购地图格、不可建设区域或用户授权范围之外施工；不得为了让方案成立而擅自购地、加钱、全部解锁、清除车辆或拆除范围外对象。
- 禁止猜测道路、分区、建筑、设施或管网 prefab 名称，也不得复用其他存档或旧会话的实体 ID、快照、预览和吸附目标。
- 关键地形、水域、污染、外部连接、资金或工具能力尚未读取时，禁止把假设坐标直接转成永久施工。

### 道路、占地与网络

- 禁止建设未接入外部道路的孤立城市路网，也不得把图面相交、线段重叠或端点靠近当作永久节点已经连通；必须回读实际道路节点与车辆可达路径。
- 禁止让规划道路、建筑主体或升级预留占地互相穿越或重叠；道路不得从住宅、商业、办公、工业或公共设施的有效占地中间穿过。
- 住宅、商业和工业开发单元及其分区范围禁止跨越铁路、高速公路、有轨电车轨道或地上地铁线路。此类设施应作为开发单元边界；线路两侧必须拆分为独立规划、分别接入道路与生命线并单独验收的开发单元，不得用一个连续分区多边形或同一内部网格跨过去。
- 禁止在同一网格内部使用比其他内部道路更宽或更窄的道路。内部横向和纵向道路必须保持一致的实际 `width_m`，从一个网格边界节点到另一个边界节点不得扩宽、收窄或插入宽度过渡段；更宽的集散路只能布置在网格外围或作为网格到外部路网的连接道路。
- 禁止沿高速公路直接连续划区、密集设置建筑出入口，或把高速公路当作低压电、供水和污水输送网络。
- 禁止把独立道路片区视为自动获得水、电、污水；来源容量存在但末端不连通时，不得继续划区或增建用量设施。
- 禁止整平全图，或仅为追求矩形外观大范围改造地形；整地只能服务已确认的道路、设施和必要净空，并须先核对水体、坡度和土方影响。

### 污染、货运与设施

- 禁止把取水设施、水塔或饮用水路径放在工业、垃圾、发电、污水或其他污染源的影响范围内；无法确认污染传播和水流方向时不得施工。
- 禁止让排污路径威胁当前或规划饮用水源，也不得把排污设施“临水”误当成污水管网已经接通。
- 禁止把穿越住宅内部道路设计成工业货车通往高速、公路外部连接或货运设施的唯一主路径。
- 禁止在没有实际道路入口、服务车辆路径或完整升级占地时放置公共服务和后勤设施；覆盖圆或直线距离不能替代路网可达性。
- 禁止把“建筑靠近道路”、图面贴路、中心距离合格、`preview_ready` 或 operation=`completed` 当作道路入口已经绑定。需要道路的建筑必须使用规划候选的精确 `road_edge_id`/`snap_target_id` 完成原生预览，并在提交后回读永久实体的 `Game.Buildings.Building.m_RoadEdge`；其为空、失效或道路类型不兼容时必须停止本阶段并修复。

### 施工与验收

- 支持原生 preview 的操作禁止跳过预览；未达到 `preview_ready`、存在错误、费用超限或吸附结果不符时禁止提交。
- 禁止并行执行永久写操作。上一项未达到终止状态并完成永久对象回读前，不得启动下一项相关施工。
- `failed`、`cancelled`、`expired` 或 `outcome_unknown` 后禁止更换 `request_id` 盲目重试；必须查询原 operation 和永久对象，结果未知时停止后续写入。
- 禁止把 `preview_ready`、已提交或 `completed` 单独表述为长期效果达成；道路与管网要回读永久连接，人口、需求、财政、污染、交通和服务效果要在模拟运行后验收。
- 禁止一次铺满全部规划分区、无需求提前建设整套高维护服务，或用无限资金、强制需求及同时修改多个变量掩盖失败原因。

## 2. 建立最小可运作片区

### 固定施工顺序

首批建设默认按以下顺序串行推进。只读勘察可以并行；永久写操作必须等待上一项完成并回读后再继续，不能把“已提交”当成“已建成”。

1. **冻结施工窗口**：记录原模拟速度，暂停模拟；确认城市会话未变化，载入开工基线和本阶段 `max_cost`。
2. **锁定走廊与边界**：确定已购地边界、外部连接点、水源和排污候选，留出主干道、第二出口、货运、公交和公共服务扩建空间；此步只勘察或预览。
3. **建设对外道路和骨架**：先接外部道路，再建片区集散路；回读永久道路、实际端点和连接关系。骨架未接通时不铺内部网格。
4. **建设生命线**：按当前 prefab 的连接层依次建设供电来源/进口与必要变电、清水来源、污水出口/处理及连接管网。分别验证生产或进口容量、输送连接和末端可达，三者不能只验证其中之一。
5. **建设本地道路和分区格**：生命线接通后再铺任务指定或按实时条件确定的小批网格；检查道路宽度、交叉口、Zone Cells 和未来升级占地。
6. **施划首批用途**：使用当前主题的精确分区名称，先少量住宅和与之匹配的岗位，再补有实际消费支撑的少量商业；污染工业使用独立货运方向。
7. **运行入住观察窗**：恢复至原速度或 `normal`，等待道路、建筑生成、迁入和企业运行；记录真实入住、岗位、需求、交通和净流量。没有真实变化时先诊断连接与需求，不重复划区。
8. **补必要服务并验收**：只补当前急需且财政可承受的垃圾、消防、医疗等设施；回读设施状态和车辆路径。满足本阶段通过条件后再进入住房—就业—消费稳定阶段。

除非当前地图机制或已解锁内容要求调整，不能把分区提前到外部道路和生命线验收之前，也不能用一次大型网格、全套服务或高容量交通设施替代第 7 步观察。

### 生命线拓扑验收

设施“已放置”不等于服务“已送达”。建设后按[公共设施与管网指南](../guides/transport/UTILITY-INFRASTRUCTURE-GUIDE.md)分别验收来源、输送和末端：

| 系统 | 拓扑顺序 | 必须回读 |
| --- | --- | --- |
| 电力 | 外部进口或发电设施 → 兼容高压网络 → 必要变电 → 低压道路/电网 → 用电片区 | 实际生产或进口、网络连接、变电状态、片区是否获得供电；不能只看全城总容量 |
| 清水 | 无污染的水源/抽水设施 → 兼容供水管网 → 跨边界连接 → 末端片区 | 取水量与可持续供给、污染、管网流量及末端可达；取水能力和输送能力分别检查 |
| 污水 | 末端片区 → 兼容污水管网 → 处理设施或排放口 | 污水流量、处理/排放能力、连接层和污染路径；排放设施可放置不证明污水已流入 |
| 独立片区 | 主网 → 跨桥、跨高速或专用走廊 → 片区入口 → 内部网络 | 跨越段和片区两端都存在永久连接，没有因高程、道路拆分或网络层不兼容形成断点 |

任何系统出现“全城容量有余但末端无服务”，优先排查网络分岛、变电/处理环节和输送瓶颈，不立即增建来源设施。

发电站、变电站、水塔、抽水站、污水处理厂和排污口优先把道路侧放在普通市政道路的功能区格子上；这样设施会直接接入道路内置的对应网络，无需另铺接驳线。同一连续普通道路网络随之获得该设施能力。高速公路不承载水、电、污水，也不能连接两个市政管网分量。未接入既有能力的道路片区，应建设本地对应设施，或延长普通道路/兼容管网接到已经通水、通电或通污水的道路。排污口和抽水站必须靠有效水域；排污口无法临路时用污水管接至道路，抽水站则必须同时临水、临普通道路。变电站的外部高压输入仍须单独验证。

### 道路交叉口与扩建预留

- 主干道承担跨片区通行，沿线接入口应集中到集散路；不要让每条本地道路或每栋大型建筑直接开口。没有统一适用于所有 prefab 的固定交叉口间距，应按道路宽度、速度、转向排队和原生预览比较候选，至少避免新接入口紧贴现有路口。
- 建筑入口与公交站应避开主要交叉口的转向和排队区。宽体设施优先使用长直路段，约 `32m` 仅作为保守起始退距，最终服从建筑尺寸、道路几何和原生 preview。
- 在图上明确保留第二机动车出口、公交走廊、工业货运通道、步行连接及未来桥梁位置。预留地保持未分区，不能用“以后拆迁”代替空间保障。
- 计划把本地道路升级为四/六车道时，先读取目标道路宽度，并用升级后的道路边界重新检查 Zone Cells、建筑退距和服务入口。道路变宽可能减少可分区深度或与已建建筑冲突。
- 首批网格的交叉口和出口只满足当前规模；复制新开发单元前重新观察排队、绕行和服务车辆路径，不因几何对称直接复制接入口。

- 路网用“对外连接—片区集散—本地街道”的分工；这是规划建议，不是游戏强制道路等级。短期用足够的道路，给升级和第二连接留位置，避免把所有工业车流引过住宅中心。
- 住宅与小规模商业靠近，污染工业独立接货运方向且与住宅可通勤；不把商业铺成整条主干道，也不让住宅完全孤立于就业和学校。
- 建立并回读水电污水真实连接。道路自带管线不代表全城已连通；检查桥隧、独立管网、变压和瓶颈。
- 先划少量当前有需求的住宅和相应岗位。发展点优先解决近期瓶颈或降低单位服务成本，而不是解锁后立即建设全部设施。

### 开发单元网格规模与连接方式

`列数 × 行数` 指 `deploy_grid_district` 的 `columns × rows`，即道路围合的街区块数量，不是 8 米分区单元数量。开发单元的行列数不按住宅密度设置固定起步值或扩展档位，应根据可建设面积、道路层级、出入口、需求、预算、公交和服务承载实时计算，并服从当前工具 schema 的实际范围。

本文所称“开发单元”，是由边界道路、内部网格、机动车出口、分区及配套设施构成，可独立预览、施工和验收的最小规划区域；下文简称“单元”。

**统一建议最大值：单个开发单元不超过 `3×3`。** 这是便于分阶段建设、观察和修复的规划建议，不是游戏或工具硬限制。确有更大连续用地需求时，应优先拆成多个相互连接、可独立验收的开发单元；若仍需超过该建议值，必须先验证路口容量、第二出口、服务覆盖、生命线余量和财政承载。

单个街区可从 `96m × 96m` 开始，并按地形、道路宽度和目标建筑占地调整；尺寸必须保持 8 米倍数且通过原生道路与分区预览。密度名称和可用道路 prefab 必须从当前城市发现，不能照抄示例名称。

开发单元之间应连接，但采用受控连接：内部本地道路保持连通，外围接入片区集散路，再由集散路接城市主干道。每个普通开发单元优先设置 2 个机动车出口，即一个主要出口和一个次要/应急出口；接近建议上限或高负载的开发单元可在路网容量验证后增加到 3 个。避免只有一个出口形成瓶颈，也避免每条内部道路都直接接主干道而制造密集路口和过境穿行。步行与公交连接可以比机动车出口更密。

工业开发单元在道路拓扑上仍须连入城市，但货车出口应直接接货运集散路、高速或货运设施，绕开住宅内部道路；住宅与污染工业之间保留商业、办公、公共设施或绿化缓冲。概括为：单元内部密连，单元之间疏连，城市主干道统一串联。

### 工业区位置筛选

工业区选址按以下顺序评估，先排除环境与网络硬伤，再比较建设成本和增长潜力：

1. **风向与空气污染**：读取当前风向和污染图层，优先把污染工业放在住宅及学校、医院等敏感设施的下风向，使污染继续远离城区。`300–500m` 可作为初筛缓冲带，不代替实时污染范围；风向不明或污染路径覆盖住宅时不施工。
2. **水源与土壤污染**：避开饮用水取水口、地下水资源和水塔。地下水抽水设施与污染工业可先按至少 `250m` 净距筛选，并按实际土壤、地下水污染范围扩大；任何候选若可能污染饮用水则直接否决。
3. **资源与产业链**：普通制造业优先靠近货运通道；农业、林业、矿业、石油等资源产业先核实当前地图的资源类型、储量、可建设范围和企业需求。不能只因存在资源就忽略污染、物流或购地维护成本。
4. **货运拓扑**：主要货运出口应通过四/六车道集散路直接连接高速、外部连接或有实际货量支撑的货运设施，另留一个次要出口供服务车辆和事故分流。内部工厂出入口放在本地道路，减少主干道沿线密集出入口；货车主路径不能穿越住宅开发单元。
5. **劳动力通勤**：工业区需与住宅保持可接受的通勤距离，同时把员工通勤和货运主流分开。优先提供独立通勤道路或公交连接；若只能经住宅内部道路到达，先重做连接方案。
6. **公用设施与城市服务**：在划区前验证电力、供水、污水、垃圾、消防、邮政和电信的真实连接、容量与到达路径。道路自带管线不证明跨桥、跨高速或独立工业片区已经接通。
7. **地形、边界与扩建空间**：选择坡度可控、整地成本合理、位于已购地块或近期可负担地块内的位置，并为第二个工业开发单元、货运设施和道路升级预留空间。避免把工业区夹在水岸、陡坡或住宅之间而失去扩展方向。
8. **需求与财政**：根据工业需求、匹配劳动力、企业库存、原料/商品流和实际货运量分批建设。先部署一个按实时条件确定规模的开发单元并观察入住、就业、库存、交通和净流量；货运站或大型道路的长期收益未被需求支持时不要提前建设。

一票否决条件包括：污染路径覆盖住宅或敏感设施、候选威胁饮用水、货车只能穿越住宅、关键公用设施无法接通，或资源产业位置没有对应资源。候选通过不等于适合大规模开发；先建设可回读的小批次，再按实际结果复制开发单元。

**通过条件**：首批永久路网与分区格有效、住户能进入、水电污水能送达；启动预算仍能支持下一个必要服务。若现金不足，缩小启动规模，不用无限资金掩盖方案成本。

## 3. 稳住住房—就业—消费循环

每次扩张先查看分密度空置、需求因子、教育分层失业/空缺、企业和服务压力。住宅需求是家庭选择的结果，不是必须填满的建设任务；商业要有顾客和消费，工业/办公要有合适劳动力。教育投资有延迟，不能用一所新大学立即解决缺高学历员工。[需求与教育机制](https://www.paradoxinteractive.com/games/cities-skylines-ii/news/dev-diary-economy-part-one)。

建议操作：

| 观察 | 下一步 |
| --- | --- |
| 住宅需求强，现房少，合适岗位空缺 | 补一批对应密度住宅，观察实际入住 |
| 需求强但空房不少 | 检查密度、租金、位置、可达性、施工和原生需求因子，先别大扩张 |
| 失业高且岗位少 | 补匹配教育的就业；区分商业、工业、办公，不只追最高税收 |
| 失业和岗位空缺同时高 | 检查教育匹配、可进入岗位、健康和通勤；先消除错配 |
| 店铺缺顾客、空置或库存积压 | 暂缓商业划区，查住宅消费、可达性和配送 |
| 学龄人口/使用率上升 | 比较附近小校与既有扩建，预留后续学段，不一次性盖全教育体系 |

密度逐步增加：低密满足有能力承担的家庭，中密可作为紧凑扩张的候选，高密放在服务与交通能承受的节点；以实时需求决定，不承诺“多盖高密就有高密需求”。重划有住户区域前先提供替代住房并估计迁移和税基损失。

**通过条件**：至少一个观察窗口内人口和实际就业均有形成或保持稳定，住房空置、失业、岗位空缺和商业经营没有同时持续恶化；住宅、岗位与消费问题能够归因并用单一小批次调整。尚未形成真实入住或企业运行时不得用继续铺区来宣布阶段完成。

## 4. 服务和公交按负载升级

先保证供水排污、电力与真实急需的消防、医疗、垃圾等服务。教育尽早纳入预算，但不用固定人口门槛同时建满所有服务。根据容量、车辆、路由、区域分配和投诉原因决定补哪一项；局部到达慢不一定是全城容量不足。

### 公共服务分批优先级

具体集中/分散、覆盖分析和选址方法见[城市公共服务设施指南](../guides/city/CITY-SERVICE-GUIDE.md)。新城按以下时序处理，而不是把所有设施集中建设成一个市政中心：

| 批次 | 处理方式 | 典型设施与门槛 |
| --- | --- | --- |
| 入住前保证 | 建成或确认已有服务可真实到达 | 电、水、污水；垃圾和基本消防应至少有明确可达方案，污染工业与高风险区不得在无消防路径时扩张 |
| 开工时预留 | 保留道路侧位置、覆盖中心和升级占地，不必立即支付维护费 | 小学、诊所、社区警务、邮局、电信、公园，以及远端片区的消防位置 |
| 需求出现后建设 | 由实际学龄人口、病患、犯罪、邮件、垃圾、死亡和休闲需求触发 | 小学、诊所、小型警察/消防、邮局、公园等社区级设施分散到需求附近 |
| 区域负载支持后建设 | 先验证客流、道路容量、财政和扩建空间 | 医院、中学、大学、总部、监狱、邮件分拣、垃圾处理和大型娱乐设施集中在区域节点或物流外围 |

学校、诊所、公园和社区警务可以组成步行可达的小型公共服务走廊，但入口应错开；医院、大学、消防总部和后勤设施分别验算车流与升级占地。社区级响应设施按真实道路阻隔分散，跨河、铁路或高速两侧不能只凭直线覆盖认为已服务。

公交先服务实际住宅—就业/学校走廊；路线力求直接、站序可达，观察车辆是否出库、拥挤和等候，再调整车辆数与班表。持续客流和财政承受能力支持时再考虑电车/地铁，预留走廊可以先于施工。公交较灵活，轨道前期投资更高，这是选择顺序的依据而非人口解锁表。[官方公共运输说明](https://www.paradoxinteractive.com/games/cities-skylines-ii/features/public-cargo-transportation)。

### 公交落地验收

按[公共交通线路指南](../guides/transport/TRANSPORT-GUIDE.md)完成线路后，不以“线路已创建”作为交付。依次检查：站点类型兼容且站序形成完整往返；站点、道路/轨道和车辆段之间存在实际路径；线路已启用并产生车辆请求；车辆实际出库并沿线运行；各站候车、累计等待、载客与回程状态合理。无车辆先查车辆段、兼容车型、网络断点和运行时段；有车无客流先查站点步行范围、住宅—岗位/学校目的地和绕行长度，不直接增加目标车辆数。

### 灾害与冗余预留

启动阶段不要求一次建齐所有灾害设施，但必须避免明显单点故障：普通开发单元保留第二出口；关键片区保留替代服务车辆路线；供电、供水和污水主通道避免全部穿过同一个易中断节点；跨河、铁路和高速分隔区分别评估消防与医疗到达。为应急避难、备用设施、疏散道路和灾后临时处理区预留土地。实际灾害风险、设施解锁和处置流程见[灾害指南](../guides/disasters/DISASTER-GUIDE.md)；未验证的冗余只能表述为预留，不能报告为已具备容灾能力。

**通过条件**：基础服务可达、容量没有持续超载、没有扩大中的严重拥堵，经营净流量趋稳或为正，下一批开发的新增维护可承担。初期暂时赤字可以接受，但应给出资金续航和明确收敛路径。

## 5. 选择下一轮增长方式

- **稳健 A**：在已服务范围内填补空地，沿现有路网复制一个小片区，新增税基实际出现后再开下一批。
- **紧凑 B**：围绕已验证客流的走廊补中密/混合用地，逐点检查学校、供水和交叉口。保留货运与服务车通道，不假设公交盈利覆盖全部成本。
- **产业 C**：按地图资源、实际配方、劳动力和贸易流选择一条小链。先追公司库存与物流瓶颈，不追求所有资源自给；货运站需有外部连接、实际货量及能承受卡车集散的道路，建站不等于没有卡车。[官方生产机制](https://www.paradoxinteractive.com/games/cities-skylines-ii/features/economy-production)。
- **多中心 D**：当现有地形或交通确实限制增长时，才规划新节点；估算桥梁/线路与重复服务的长期成本，给每个节点一定本地就业和生活服务。

每轮交付记录：策略、选址理由、预计与实际成本、新永久对象、已入住单元/岗位变化、服务和交通变化、继续扩张条件。建设后反馈若与预测相反，缩小批量并更新假设，而非同时加税、扩区、造学校和修高速来碰运气。

### 专门产业和建筑附属区域

垃圾填埋场储存区、农业/林业/矿业/石油采集区等属于 owner 建筑的附属区域，不是行政区或普通 zoning。先完成并回读永久 owner 建筑，再按[建筑附属区域指南](../guides/buildings/BUILDING-AREA-GUIDE.md)执行：`list_building_areas` 发现兼容的精确 `area_prefab` → `preview_building_area` 校验边界、资源、容量与费用 → 提交并轮询 → 用永久 `area_id` 回读。资源产业边界必须覆盖相应自然资源，填埋区避开住宅和饮用水源，两者都要为道路、加工建筑、车辆出入口和扩容留空间。区域创建成功只证明边界已提交，运行模拟后再验收产量、储量、利用率与货运效果。

**通过条件**：本轮只执行了一个明确增长策略，新增永久对象和实际费用已记录，模拟结果未破坏 `S3 服务稳定` 的门槛，并且下一轮的需求、承载余量和预算来源明确。不满足时进入恢复状态，不同时启动第二种增长策略。

## 工具化执行入口

工具只缩短调用往返，不改变状态机和验收标准。完整参数、副作用和输出见 [`tools/README.md`](../../tools/README.md)，批量工作流见[高效建设与增长](efficient-deployment.md)。

| 场景 | 首选入口 | 使用边界 |
| --- | --- | --- |
| 比较住宅、商业或工业候选地 | `node tools/survey-space.mjs` | 首次开发、旧城或碰撞敏感位置用 `full`；`quick` 只生成 `UNVERIFIED` 候选，仍须原生 preview |
| 提示词指定 `N×N` 网格和道路类型 | MCP `deploy_grid_district` | 先发现精确道路与分区 prefab；底层道路、分区和建筑 operation 仍须逐项达到 `completed` |
| 使用配置文件重复部署街区并观察增长 | `node tools/deploy-district.mjs` | 只在用户已授权修改城市时运行；历史坐标和实体 ID 不可复用，后续失败不会自动撤销已完成对象 |

## 新城启动完成定义

同时满足以下条件时，才将城市从“新城启动”转为“常规运营”；达到单个人口里程碑、道路铺完或资金仍为正都不能单独判定完成：

- 外部道路、电力、清水和污水均有永久连接，来源、输送和末端状态已回读，没有已知单点断路。
- 已出现真实居民、住房占用、企业和岗位，住房—就业—消费循环可以观察，主要错配没有持续恶化。
- 垃圾、消防、医疗等当前必要服务真实可达，已出现的容量压力有明确处理方案；公共服务和交通预留未被占用。
- 主要通勤、货运和服务车辆路线可用，没有持续扩大的严重拥堵；已建设公交时车辆能够实际出库并完成线路。
- 当前资金和净流量能够承担现有维护；若仍暂时赤字，已记录可量化的续航时间和收敛条件。
- 本轮所有 operation 均已处于终止状态，永久对象、实际费用、模拟速度和新基线已记录；不存在未处理的 `outcome_unknown`。

完成后进入以 `S3` 为最低健康门槛的常规增长循环。任一条件后来失效，回到 `R 恢复`，而不是继续扩大分区。

## 统一阶段状态机

下面的状态机是通用执行入口；本页各章节提供每个状态的具体规划方法，后文“四步法”只是特定存档案例。状态只能在退出条件满足后前进；暂停条件出现时进入 `R 恢复`，不得带病扩张。

| 状态 | 进入条件 | 允许动作 | 退出条件 | 暂停或回退触发 |
| --- | --- | --- | --- | --- |
| `S0 勘察与立项` | 城市已加载且能力可查询 | 建立基线、比较候选、预览启动包、设预算与存档点 | 本页“开工基线”通过，得到可执行启动方案 | 会话变化、关键数据未知、候选越界、污染/水源硬冲突、启动包不可负担 |
| `S1 骨架与生命线` | `S0` 通过且用户已授权施工 | 按固定顺序建设外部道路、骨架、生命线、本地小网格和首批分区 | 永久路网与 Zone Cells 有效，首批住户可进入，电水污真实送达，仍有必要服务储备 | 任一生命线断开、道路无外部路径、永久结果不明、预算跌破储备 |
| `S2 启动循环` | `S1` 通过且模拟可运行 | 观察迁入、企业、就业、消费与需求，小批修正住宅/岗位/商业 | 连续观察窗口内有真实入住和就业，供需没有持续恶化，问题原因可以解释 | 空置与扩建并存、失业和岗位错配恶化、商业无顾客、连续赤字无收敛路径 |
| `S3 服务稳定` | `S2` 已形成基本税基和实际服务需求 | 按负载补基础服务和公交，检查容量、车辆与路径 | 基础服务可达且未持续超载，无扩大中的严重拥堵，净流量趋稳或资金续航明确 | 服务车辆无路径、关键容量持续超载、拥堵扩大、维护费超过新增税基承载 |
| `S4 受控增长` | `S3` 通过且存在明确需求、预算和承载余量 | 从稳健、紧凑、产业或多中心策略中只选择一轮，分批建设 | 本轮永久对象和模拟效果均已验收，仍满足 `S3` 条件；随后以新基线开始下一轮 | 指标与预测相反、多个领域同时恶化、出现新的单点故障或无法解释的需求变化 |
| `R 恢复` | 任一状态触发暂停条件 | 停止新建，识别最后已完成操作，修复连接/容量/预算或缩小方案 | 故障已消除并重新建立基线；返回触发故障的原状态重新验收 | 结果仍未知、修复会扩大授权范围、需拆除永久对象或只能加载旧存档 |

每次状态转换都记录：来源状态、目标状态、查询时间和会话、关键指标、operation/request ID、实际费用、新增永久对象及下一状态的预算上限。时间经过本身不构成通过；预览成功、命令已提交或道路几何看似相连也不能单独推动状态。

## 失败回退协议

回退目标是返回“最后已知良好状态”，不是机械地删除本轮全部对象。跨领域建设可能部分成功，删除道路、建筑或分区也可能产生二次影响，因此先核验再处理；具体事务状态和错误码处置见[调用、事务与诊断](operations.md)。

1. **预览失败**：城市尚未改变。保留错误和候选数据，取消不再使用的预览，调整位置、尺寸、prefab 或前置网络后重新预览；不得跳过原生校验直接施工。
2. **提交失败或超时**：使用原 `operation_id` 和 `request_id` 查询原事务，并回读目标永久对象。`outcome_unknown` 时停止后续写入，不能更换 ID 盲目重提；只有确认未创建后才能重新规划。
3. **批次部分成功**：立即停止批次后续步骤，列出已完成、失败和未知的每个操作，核对实际费用与永久对象。对安全且有用的已完成对象可保留；拆除、迁移或加载旧存档需要用户授权，不能假设整批自动回滚。
4. **道路或生命线失败**：停止新增分区并暂停扩张，先恢复外部道路、电、水、污水及服务车辆路径。跨桥、跨高速或独立片区分别检查网络连通、生产/进口容量、输送瓶颈和末端状态；修复后重新执行 `S1` 退出验收。
5. **入住、需求或经济失败**：保持现有永久网络，停止购买土地和新增高维护设施，运行有限观察窗并一次只调整一个变量。优先缩小下一批、填补既有服务范围和修复错配；不得用加钱、全部解锁或同时修改税率、分区与服务来掩盖原因。
6. **服务或交通失败**：先分辨总容量、局部路径、车辆调度和土地利用问题。无路径先修网络，局部慢先修覆盖或路口，持续满载才扩容；公交无客流先查站序、车辆段连通和住宅—目的地关系，不直接加车。
7. **无法就地恢复**：保持城市暂停并报告当前状态、已产生费用和不可逆对象。若修复需要扩大授权范围，停在 `R` 等待决定；只有用户明确选择后才拆除对象或加载阶段前存档。

完成恢复后重新采集受影响领域的基线，不沿用故障前快照；若城市会话已经变化，所有实体 ID、快照和未完成 operation 均视为失效并重新发现。没有待处理事务且用户未要求保持暂停时，恢复进入施工窗口前记录的模拟速度。

## 实战落地：从零建城自然晋级四步法（Field-Tested 4-Step Progression）

基于马沙姆市（版本 1.19.0）从人口 0 到 2,000 人、国库超 ₡200 万且最终幸福感 67 的全闭环实机验证，整理以下四步进阶流程。这里的设施名称和阶段仅是该存档的示例，实际应以当前存档的解锁状态为准：

### 第一步：骨架路网与生命线物理隔离
1. **外部道路引出**：从高速公路接口延伸 4 车道双向干道（`Medium Road`）进入开发地块，再正交分支展开双向生活街道（`Small Road`），所有端点与交叉口保持 8 米格网模数对齐。
2. **净水与排污隔离**：内陆高地的水塔（`WaterTower01`）和岸边排污口（`SewageOutlet01`）优先把道路侧放在已连通普通道路的功能区格子上，直接使用道路内置给水/污水网络，不另铺接驳管。排污口必须临水；受岸线限制不能临路时，才按连接层用兼容污水管接到已经通污水的道路。抽水站必须同时临水和临普通道路。
3. **变电站安全岛**：变电站（`TransformerStation01`）置于远离居住区的独立地块，用专用单行/双行短支路接入路网；紧邻该道路功能区格子后，低压侧直接接入道路内置线路。高压侧若尚未接入外部高压走廊，仍须使用当前城市实时发现的兼容高压网络完成连接。

### 第二步：主题分区激活与自发入住（Milestone 0 → 1）
1. **主题绑定**：调用 `get_city_configuration` 确定地图风格（如 `European` 或 `North American`），并从 `list_zone_types` 获取对应名称。
2. **低密起步**：首批沿街施划 2~3 个低密度住宅开发单元（如 `EU Residential Low`）和少量街角低密度商业（`EU Commercial Low`），坚决不用泛型名称。
3. **首批人口入驻**：放开模拟速度至 `normal`，等待住户迁入、自建房屋拔地而起，达成第一里程碑解锁基础公共服务。

### 第三步：梯次市政服务与中密升级（Milestone 1 → 3）
1. **服务梯次落位**：
   - 里程碑 1：先从 `list_city_service_prefabs` 选择已解锁的医疗、垃圾和殡葬设施；本次验证使用 `MedicalClinic02`、`Landfill01` 和 `Cemetery02`；
   - 里程碑 2：选择已解锁的小学等教育设施；本次验证使用 `ElementarySchool02`；
   - 里程碑 3：选择已解锁的消防和警察设施；本次验证使用 `FireHouse01` 和 `PoliceStation02`。
2. **路口避让与候选回退**：宽体建筑应优先部署在长直路段，32m 可作为保守起始退距；最终以原生预览为准，并遍历 `candidate_count` 返回的候选。
3. **中密承载跃升**：在服务覆盖完善的主干道两侧施划中密度联排住宅（`EU Residential Medium Row`），推动人口迅速突破 1,000~2,000 人。

### 第四步：环保型下风向工业园与重载闭环（Milestone 3+）
1. **下风向测定**：调用 `get_climate_state` 确认恒定风向矢量，优先将工业园区布置在居住区下风向，并结合污染、水体和地下水图层评估与水塔/水源的距离；500m 仅作为本次验证的保守起始参考。
2. **货运通道直连**：从高速公路接口分流出专用 4 车道货运道路直达工业园，与生活区路网物理分离，实现重卡零穿城。
3. **按需分批施划**：适度施划 `Industrial Manufacturing`，满足市内工业品原料与就业需求，形成“就业—居住—消费”完整正向经济循环。
