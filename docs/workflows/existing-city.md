# 接手发展中的城市：保留运转能力，先诊断再修复

先读 [策略选择与评估](development-strategies.md)。适用于正常成长、停滞、财政赤字、拥堵或补丁迁移后的城市。接管请求不等于允许拆掉全城或改变用户的风格与游戏模式。

## 1. 建立接管基线

读取配置、会话、人口趋势、经常收支、现金、贷款、地块费用、密度空置、教育分层就业、关键服务、主要交通走廊。只对有问题领域深入抽样公司、家庭、车辆和路径，别为“全面了解”先导出所有 ECS。

记录用户目标和保留范围、当前模拟速度、已知改动、是否刚升级游戏/模组。仅在实施需要时暂停；诊断本身不必改变状态。大型重建若需要回滚依赖用户已有存档或实际可用保存能力，不能声称 MCP 已备份存档。

先分类：正常扩张用 A/B/C/D；有系统性危机用 E。现金富余但亏损、人口增长但失业/通勤恶化，都不能当作健康增长。

## 2. 先处理不可等待的问题

优先级建议：正在发生的生命线故障/灾害和通道中断 → 即将断裂的现金 → 关键服务积压 → 住房岗位错配 → 普通增长与美化。并行问题按发生速度和损害范围排序，不机械地先修所有道路。

- 缺电、缺水、污水倒灌：先查连接和输送，确认是产量不足还是送不到。修一处断点通常比新建整套设施更小，但需实证。
- 集中疾病：先查污染水源和污染范围，再看医院；医疗扩容不能修复污染源。
- 垃圾/遗体积压：查设施状态、车队、处理余量、分区服务范围和路线；不要只看覆盖颜色。
- 灾害：读取事件类型和影响，按用户授权做应急恢复。默认用正常响应、通路和原生重建，不自动关闭自然灾害或强制清除伤亡标记。

## 3. 财政修复：先算持续成本

把收入支出拆成服务、道路/设施、地块、进出口、贷款及一次性项目，定位最大几项变化。暂缓可选建设；在不切断唯一服务的前提下，试调过剩预算或停用闲置设施，回读节省与服务代价。先考虑可恢复调整，后考虑拆除。

对刚经历经济重构的旧档，税基、企业规模和家庭住房可能需要模拟适应；现金允许时先观察，不能因一次跳变全城重划。持续租金问题要检查收入/就业和替代住房，而不是只提高地价或直接发钱。[官方旧城适应说明](https://www.paradoxinteractive.com/games/cities-skylines-ii/news/dev-diary-economy-part-two)。

提税仅做小步相关类别试验；若税基流失大于税率收益就回调。贷款可桥接有依据的短期缺口或必要工程，但先估算还本付息后的净流量；不靠连续借新还旧维持结构性亏损。普通 MCP 购地功能不等于支持退地，不能把“卖掉地图格”写成已可执行的修复。

**离开危机阶段的条件**：关键服务恢复，资金续航覆盖恢复期，连续可比样本的经营净流量改善且不靠一次性奖励撑起。若仍不够，缩减可选计划并明确剩余缺口。

## 4. 按症状检验原因

| 症状 | 优先核实 | 最小干预候选 | 不要直接下的结论 |
| --- | --- | --- | --- |
| 人口停滞、住宅需求低 | 分密度空置、负向因子、迁出、可负担住房、岗位、版本变化 | 修负向因素或补缺的住房类型 | 必须强制需求/刷人口 |
| 空房多且有人无家可归 | 收入、租金、家庭结构、住房可达性和可用状态 | 替代住房、通勤/岗位改善 | 空房数量够就没有住房问题 |
| 企业缺工而失业高 | 教育级别、累计可进入岗位、健康、到达路径 | 学校/合适岗位/公交或连接 | 全城一定缺人口 |
| 店铺缺顾客 | 消费、商品种类、位置、库存、停车与公交可达性 | 暂缓新增店面，修消费或到达瓶颈 | 需求条高就继续铺商业 |
| 企业缺原料或库存高 | 配方、贸易、交付路径、仓储周转、利润与版本问题 | 一处货运连接或匹配生产/消费节点 | 修货运站必然解决所有缺货 |
| 财政好但幸福度下滑 | 分区污染、住房负担、服务、税费和出行 | 找出影响最大的具体片区 | 降所有税或盖全部服务 |

把问题解释为可检验假设。例如“工业区缺工源于通勤断路”需要道路/路径证据，修复后看员工实际到岗；“有大学”不等于存在所需数量的已毕业劳动者。

## 5. 拥堵修复：从队尾向下游查

圈定排队开始点、受影响方向和目的地；查下一路口、出口、停车入口、公交停靠和事故。区分普通高流量、持续排队、无路径与服务车受阻，不为一个全城交通百分比大拆迁。

建议从小到大试：修断路/错误单行和转向 → 调整冲突路口与入口 → 增加有意义的平行通道或第二片区连接 → 改进实际通勤走廊公交 → 最后才加宽、立交或大型货运设施。新通道需有可用下游容量；否则只是把队列搬走。

不要把所有路口换环岛或信号灯。停车是出行选择的一部分，涨价前先有可达替代；公交看出库、实际路线、等候和满载，不只看线路已创建。车道速度可能被模拟重算，固定速度/瞬时清车不能证明持续通畅。[寻路与停车机制](https://www.paradoxinteractive.com/games/cities-skylines-ii/features/traffic-ai)。

施工前记录同一模拟时段的车辆数、停驶车辆数、平均速度和卡住车辆数；改造后在可比时段复测。道路事务 `completed` 只表示永久施工完成，不等于高峰交通已经改善。

施工保留关键通道，按片区推进。改路后核实永久节点与边、建筑道路接入、分区格、服务车辆可达性和下游路口；给车辆重新寻路和走完拥堵路段的时间。一个入口变好但队列集中到下一个汇合口，应转为路口治理，并记录为转移瓶颈而非继续扩大入口。

## 6. 恢复增长与结果交付

旧片区有服务和可用土地时优先填补；中心已经过载则做渐进更新或新节点。先补替代住房/岗位和交通，再逐块重划；避免一次拆迁造成迁出和税基丢失。只在有需求、有效容量、资金与连接时扩张。

每轮记录五项：

1. 基线与主要原因，区分证据、推测和未知。
2. 实际修改、operation ID、永久对象及一次性/持续成本。
3. 前后同口径指标及模拟经过时间。
4. 已恢复功能和仍存在的问题；区分即时回读与长期效果。
5. 下一阶段选择、继续条件与停止条件。

两轮可比观察仍无改善时，建议先重新检查机制、样本和版本，而非不断扩大同一种干预。官方也将物流问题区分为资源、企业决策和路线等原因；存在模拟缺陷时，不把所有异常归咎于规划。[官方模拟问题说明](https://www.paradoxinteractive.com/games/cities-skylines-ii/news/collected-questions)。

用户只要求方案时，交付分阶段计划和待核实项，不执行修复；没有游戏连接时，不能以旧测试存档“沃本”的数据代替当前城市。
