# 规划计算缓存

这些缓存自动工作，Agent 无需传递缓存对象或更改施工步骤。重启 MCP 后冷启动，不需要重建游戏模组。用 `inspect_planning_cache` 查看命中、未命中、淘汰和估算内存占用。

## 1. 缓存范围

| 对象 | 复用条件 | 上限与边界 |
|---|---|---|
| 不可变 plan、snapshot、evidence 解析结果 | 引用一致，当前文件字节哈希一致 | 默认估算 32 MiB、128 条；LRU；返回深拷贝 |
| HTML/SVG 渲染元数据 | 完整快照、规划、渲染参数、格式和渲染器版本一致 | 估算 8 MiB、64 条；只保留元数据；相同请求共享 Promise |
| 道路、建筑、水域、地形空间索引 | 四个输入图层内容哈希一致 | 估算 32 MiB、8 条；输入先复制；不跨进程保存 |
| 编译后的施工批次 | 同次准备施工使用内部编译结果；后续批次使用施工日志中的编译结果 | 不向模型开放 compiled_plan 输入；审批哈希、执行器版本校验仍保留 |

内存字节为保守倍率估算，不是 V8 堆内存的精确上限；超出单条预算的数据不缓存。运行时实现变更后应重启 MCP，渲染语义变更需更新渲染器版本。

## 2. 完整性与实时性

- 不可变记录命中时仍读文件并计算字节哈希，以检测删除、篡改及相同长度的修改；省去重复 JSON 解析和规范化哈希，不宣称消除文件 I/O。
- 渲染命中仍校验文件 SHA-256；产物丢失或内容改变时重新渲染。其他文件访问错误向上报告，不伪装成成功。
- 空间索引仅回答传入快照对应的问题；内容指纹不是游戏实时 revision，也不会延长 snapshot_ref 的有效期。
- construction 日志每次从磁盘读取，锁、状态版本、in_flight 和恢复要求不变；不能作为普通缓存淘汰。
- 设施、端口等既有单次工作流局部变量保留，不新增跨施工操作的实时状态缓存。资金、暂停状态、解锁校验、碰撞、原生 preview、operation、commit 和永久对象回读仍遵循原实时流程。

## 3. 验证与收益口径

运行 `node --test mcp/test/*.test.mjs`。专项测试覆盖 LRU/字节淘汰、对象隔离、文件篡改、可变日志更新、并发渲染合并、产物修复、渲染参数变化、目录默认值和图层变化。

缓存计数用于定位重复工作，不等于模型 token 或游戏端到端收益。实际桥接统计读取 `inspect_prefab_catalog_cache`；本工具不查询游戏。此次优化主要减少重复解析、编译、渲染和建索引，实时施工性能仍需在游戏中测量。
