# Prefab目录缓存

`mcp/prefab-catalog-service.mjs` 提供进程内共享的城市会话目录缓存。建筑规划、城市按图施工、网格预检/施工、公用设施接驳、综合基础设施与服务集群工作流以及MCP目录查询使用同一服务；相同底层查询函数共享实例。原有两套会话内无限期建筑缓存已移除。

## 当前行为

本项目按单Agent连接使用。目录缓存只存在于当前MCP进程的内存中，不引入跨进程目录锁、共享磁盘目录缓存或分布式协调。单Agent的高层工作流仍会并行读取目录，所以保留Promise合并及generation保护。

MCP进程重启后从冷缓存开始；游戏换档或重载后必须先读取状态，按新 `session_id` 重新发现目录。观察到城市未加载、会话变化或桥接不可用错误时清除会话缓存。缓存命中本身不会主动探测游戏是否换档，不能省略工作流入口的实时状态检查。施工日志是独立的持久化记录，不能随目录缓存清理；旧会话的实体ID和operation不得直接续用。

- 只缓存道路、建筑、市政/交通/公用设施、管网、分区、轨道和航道的 **prefab目录响应**。真实道路/建筑实例、地形、Zone Cells、资金、服务覆盖、道路绑定、管网连接及负载不缓存。
- 正常条目默认30秒；空结果、已锁定条目或 `unlocked_only=true` 查询默认5秒。已解锁不是永久有效。最多512个查询条目，超量淘汰最早条目；返回深拷贝，调用方不能修改缓存。
- 键包含当前 `session_id`、工具和完整查询参数指纹，分页、筛选类别及锁定筛选不会混用。同一查询的并发请求共享Promise。
- 空结果只有在响应成功、未截断且该查询分页完整时才缓存；超时、失败及不完整空页不记为“不存在”。`exact` / `getRoad` / `getBuilding` / `getUtility` / `getZone` 会跟随分页查找精确名称，锁定条目与不存在分别返回；类别歧义仍由业务工作流检查。
- `resolveMany` 合并调用者的查询组织方式，但内部仍为多次桥接调用，不声称已实现游戏侧批量RPC。
- 状态查询发现会话改变或城市卸载时立即清空。generation阻止旧查询在清空或强制刷新后回写，也不允许迟到结果把会话切回旧城市。
- 经本服务执行的配置、经验/发展点和解锁操作在调用前使目录缓存失效，包括该写入随后超时的情况。普通道路/建筑实例增删不清空资产定义缓存。
- 原生查询/预览报告prefab不存在、锁定或相关类别不匹配时失效缓存；工作流仍按原有失败规则停止，不自动用新ID重试。
- 刷新时若发现已观测资产的关键几何字段变化，返回 `CATALOG_GEOMETRY_CHANGED` 并清空缓存。此时应停止并重新检查获批规划；不得把刷新后能放置等同于仍符合旧审批。

## 检查和刷新

`inspect_prefab_catalog_cache({refresh:false})` 返回当前进程的会话、generation、条目数、进行中查询数、命中/未命中/合并/失效统计。`refresh:true` 清除观测缓存并递增generation，不修改游戏。

内部查询接受 `{force_refresh:true}`。强制刷新不会复用旧Promise；旧查询结束后被拒绝写入。长期运行的MCP进程才能持续受益；新建的stdio进程从冷缓存开始，多个进程目前不共享目录缓存。

## 正确性边界

目前没有游戏侧可靠的资产目录和解锁事件版本，因此 **未启用跨会话静态磁盘复用，也未宣称实时获知玩家或其他模组的全部变化**。版本号、资产名列表和内容哈希不能自动替代游戏事件。TTL内仍可能发生外部变更；原生预览必须实时检查可用性、费用、坡度和碰撞，提交后继续永久对象、绑定与连接验收。资产变化后优先显式刷新再重新规划。

基础尺寸/规则不等于现场放置结果，基础价格不等于预览费用；建议朝向不等于候选朝向；实体ID不能跨会话复用。地图实例增删后需要重新读取相关局部地图、拓扑和碰撞；目录缓存不是地图缓存，也不会使规划快照自动更新。

如需进一步优化，优先增加游戏侧轻量目录/可用状态版本和批量验证；目前不计划跨会话磁盘预热。不要通过定时全量扫描目录来假装轻量版本检查。

验证：运行 `node --test mcp/test/*.test.mjs`。新增测试覆盖并发合并、隔离副本、TTL、迟到查询、完整负缓存、分页、锁定状态、实例与目录失效的区别、几何变化及超时。缓存统计衡量查询复用，不代表模型token数或游戏端到端性能。

## 规划计算缓存与目录缓存的分工

- 管网连接流程不再额外持有永久 prefab Map，统一遵循本服务的 TTL 和失效规则。
- 道路与分区目录按已声明默认值规范化参数；不同分页、筛选和限制仍使用不同键。
- `inspect_prefab_catalog_cache` 的 `bridge_queries` 统计经该实例实际转发的查询（包含状态与非目录工具），`bridge_duration_ms` 为这些调用的累计耗时，包含失败；不等于仅目录查询量或请求墙钟耗时。
- 规划记录、渲染文件和空间索引的复用见 [规划计算缓存](planning-computation-cache.md)。它们不替代实时施工校验。
