# 城市建筑、分区与道路检查清单

用于公共服务建设、住宅/商业/办公/工业开发以及道路改造。以下是操作与验收要求；布局建议不代表游戏硬性规则，也不表示已经实现全城自动优化。

## 公共服务与独立建筑

- 先确认真实需求、现有容量与利用率、建设和维护成本，再决定新增、升级或调整布局。人口目标不能直接换算为固定数量的学校、医院或消防站。
- 选址可使用现有贪婪排名，但它只是在有限候选池内比较覆盖/需求代理，不保证全局最优。道路阻隔、服务车辆路径、污染、升级空间、第二出口和未来道路走廊仍须独立检查。每座建成后重新读取需求和候选，不能把旧覆盖快照用于整批设施。
- 使用规划器精确候选进入原生预览；建筑本体之外，还检查停车贴花、隐形通道、附属对象和升级占地。建成后检查永久道路绑定及实际水电污水需求，不能只验建筑中心点贴路。
- 用户所说的升级名称不一定是该资产的模块。先列出主体兼容升级、已安装数量、重复安装规则和原生位置；不存在的模块不能擅自替换成另一建筑。“全部升级”按当前兼容、已解锁且可安装的模块处理，逐项记录完成或受阻原因。
- 行政区内的建筑归属与服务工作区是两项数据。按实时行政区成员和支持能力筛选，再读取/设置服务区；不支持该设置的设施单列。`set_service_districts` 替换整个列表，空列表代表全域服务，不能当成“未设置”。新增设施、搬迁或重画边界后重新核对。
- 接口提交成功后还需观察实际容量、使用者、车辆与路径；覆盖圆和容量标称值都不能证明服务已到达目标居民。

详见 [建筑指南](../guides/buildings/BUILDING-GUIDE.md)、[公共服务指南](../guides/city/CITY-SERVICE-GUIDE.md) 与 [行政区指南](../guides/areas/DISTRICT-GUIDE.md)。

## 住宅、商业、办公与工业

先区分普通可成长分区与直接放置的独立/特殊建筑。不能把划区格数、建筑数量、住房容量、已入住人口、岗位容量和实际就业混为同一指标。

| 用途 | 规划与复查重点 |
| --- | --- |
| 住宅 | 当前住房空置、入住、密度与人口目标；分批划区并观察增长，接近目标时先检查已有待成长地块，不继续机械扩张 |
| 商业 | 当前商业需求、企业经营/空置、居民可达性和配送路径；不把商业面积增加直接等同于稳定收入 |
| 办公 | 当前需求、可用劳动力与教育结构、通勤路径；区分规划岗位、已生成企业岗位与实际就业 |
| 工业 | 当前需求、劳动力、实际污染与风向/水源、货运进出路线；专业产业资源区按专用工具与资产规则处理 |

- 区域名称必须来自当前 `list_zone_types`；主题前缀只是部分资产命名方式，不是必填格式。列表返回的无前缀名称同样可以是正确名称。
- 先建成道路并回读永久边，再用 `analyze_zoning_cells` 检查实际格子、道路侧、深度、阻挡、占用和现有用途。道路的 left/right 相对其起终方向，不是地图固定东/西；网格外围外侧不应默认一起划区。
- 为公共服务、升级、道路扩宽和第二出口保留地块。道路宽度、坡度、交叉口及原生格子生成结果都影响可用空间；名义网格尺寸不保证完整分区。
- `overwrite` 与 `include_occupied` 会改变现有用途，必须符合此次改造范围。不要为了让预览有改动而覆盖已入住区域或清除预留用地。
- `completed` 只证明格子写入。推进模拟后另查建筑成长、入住/企业/就业、水电和道路状态；未成长时先查需求、格子条件及网络，不直接归因于名称或盲目再划更多地。

接口与批次规则见 [分区指南](../guides/areas/ZONING-GUIDE.md) 和 [高效建设流程](efficient-deployment.md)。

## 道路、新出入口与沿街改造

- 以交通角色和实际连接确定主干道清单，不仅凭车道数或屏幕可见范围；“全部主干道”应列出纳入、跳过及原因，防止漏掉短段、双向配对边或误改高速匝道。
- 改直入口、加宽或新增出口前，沿行驶方向找真实队首与下游瓶颈。第二出口须验证两个方向的连续路线，不能只看到新增匝道就认定分流成功。
- 用户指定交叉路口菜单预设时，使用实时目录中支持的原生资产；核对方向、占地、坡道和现有网络接入。预设本体建成后，还要检查所有计划使用的外部端口是否接通。
- 整地、拓宽、换 prefab 或重建前记录相邻建筑入口、分区、站点、管网及公交线路。完成后重新发现永久边，检查这些依赖是否保留；不假设 ID、分区格和道路附着对象始终不变。
- 停车改自行车道时，先确认道路支持的选项及互斥关系，按用户指定左右两侧与方向处理。用 `inspect_road_lanes` 和相关永久数据检查实际停车车道、自行车车道及方向；“两侧各一条”不能默认为“每侧双向两条”。检查路口、桥梁、短段和断头处的连续性，而非只看名称变化。
- 移除沿街停车后观察实际停车与接送需求；自行车设施也须检查合法道路侧位置和步行接驳。公交顶棚属于道路站点时使用道路站点接口，不能用公交站建筑替代。
- 跨公路或铁路的道路明确采用哪种交叉方式，并验证坡度、净空、桥头连接和层级；二维相交不证明连接或合法跨越。

相关接口见 [道路指南](../guides/roads/ROAD-GUIDE.md)、[道路站点与交通设施](../guides/transport/TRANSPORT-INFRASTRUCTURE-GUIDE.md)。

## 统一验收与报告

记录同一口径的施工前后状态、操作 ID、费用、永久对象和模拟经过时间。依次区分“命令完成 → 几何/绑定正确 → 网络可达 → 有效服务或增长 → 持续经济效果”。维护费和收入变化须观察后再下结论，不能用建设完成证明经济转正。

失败或结果未知先核查原操作；保持已完成工程，不自动扩大拆迁范围。网页更新为实际结果，明确待建和未验证项。会话切换后重新发现实体；道路合并导致绑定 ID 变化时核验新边，不能直接重建重复建筑。铁路专项另见 [铁路站区检查清单](../guides/transport/RAIL-STATION-CHECKLIST.md)。
