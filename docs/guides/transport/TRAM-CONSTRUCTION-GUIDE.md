# 有轨电车规划、施工与运营验收指南

本指南用于通过 CityWeaverMCP 规划和建设可实际运营的有轨电车系统，覆盖车辆段、道路嵌轨、独立轨道、道路侧站点、闭合线路和车辆运营。资产名称、费用、尺寸、坡度、长度及解锁状态必须从当前城市实时查询；文中的流程不是固定 prefab 清单。

有轨电车系统只有同时满足“车辆段可出车、轨道连续、站点兼容、线路双向可寻路、车辆实际运行”才算完成。道路出现轨道纹理、站点放置成功或线路显示 `complete=true`，都不能单独证明系统可运营。

## 1. 完成标准与建设顺序

推荐顺序：走廊勘察 → 线路和车辆段总体规划 → 道路/独立轨道施工 → 轨道永久回读 → 车辆段建设及接轨 → 站点建设 → 线路预览与提交 → 实际运营验收。

| 阶段 | 必须取得的证据 |
| --- | --- |
| 走廊可建 | 当前城市存在已解锁 Tram 轨道、车辆段、站点和线路 prefab；预算、地形、道路及空间允许施工 |
| 轨道建成 | 永久道路具有 `TramTrack` 和实时 Tram `TrackLane`，或永久独立轨道类型为 Tram；交叉口和接头形成真实连接 |
| 车辆段可用 | 永久车辆段存在，内部 Tram 轨道与线路网络连续连接，道路及城市服务接入有效 |
| 站点建成 | 永久站点具有 `TransportStop`、`ConnectedRoute`、`TramStop`，并附着到目标永久有轨电车道路 |
| 线路建成 | 原生线路操作 `completed`，站序和线路 prefab 正确，永久线路 ID 可回读 |
| 线路可寻路 | 所有相邻站段及闭合回程均有有效路径；没有空 `RouteLane`、断轨或错误方向 |
| 系统运行 | 兼容电车从车辆段出库，按站序运行、上下客并能继续或回段；没有持续卡住或无路径 |

城市写操作期间保持暂停并使用默认选择工具。每个 preview 保存原 `operation_id` 和稳定 `request_id`；改变几何、道路、站点、轨道 prefab 或站序时必须新建预览，未知结果只能查询原操作。

## 2. 施工前发现与总体规划

1. 调用 `get_game_status`、`get_query_capabilities`，记录城市会话、原模拟速度和可用工具。
2. 用 `list_transport_track_prefabs(track_type="Tram")` 发现独立电车轨道；记录精确名称、宽度、最大坡度、长度、高程和单位费用。
3. 用 `list_transport_facility_prefabs` 查找当前已解锁 Tram Depot 或其他兼容车辆段，读取放置模式、尺寸、费用及内部轨道能力。
4. 用 `list_road_stop_prefabs(transport_type="Tram")` 发现道路侧电车站点；确认 `requires_tram_track=true`。
5. 用 `list_transport_line_prefabs` 选择精确 Tram 客运线路 prefab，读取默认车辆数和最小站距。
6. 查询现有道路、道路车道、永久 Tram 轨道、站点和线路，避免重复升级、重叠轨道或误接其他交通模式。

总体方案必须同时画出主线、回程、折返/闭合方式、车辆段支线、全部站点、主要路口和乘客步行接驳。先证明车辆段能够接入完整线路，再施工远离车辆段的轨道；不能最后才发现车辆段没有合法接轨空间。

### 2.1 选择道路嵌轨或独立路权

| 方案 | 适用情形 | 主要风险 |
| --- | --- | --- |
| 道路嵌轨 | 已有连续城市道路、站点需要直接服务沿街客流、希望减少额外占地 | 与机动车共享路口和拥堵；并非所有道路支持轨道升级；道路替换后实体 ID 可能变化 |
| 独立轨道 | 有连续保留走廊、需要避开拥堵或跨越复杂地形 | 需要额外用地、曲线和坡度控制；道路侧站点工具不能直接放在纯独立轨道上 |
| 混合走廊 | 市中心嵌轨、外围独立路权或车辆段支线 | 两种网络的接头、方向、坡度和站点兼容性必须逐段由原生预览和线路寻路验证 |

道路嵌轨升级一次在道路两侧添加一对方向相反的 Tram 轨道，不提供单侧电车轨道选项。若设计只需要单向运行，应从实时目录选择兼容的独立单向轨道或重新设计线路，不能把双向道路升级误报为单向轨道。

## 3. 轨道几何设计

- 轨道在图面上相交不等于连接。端点必须吸附到同一永久节点，或通过原生施工形成可回读的连接车道。
- 禁止用直角折线模拟弯道。独立轨道曲线默认按 `min_radius_m=150` 做 MCP 采样检查；这是保守设计值，不是所有资产的统一游戏标准。显式调整时仍须满足 prefab 和原生预览。
- 每段的长度、坡度和允许高程以 `list_transport_track_prefabs` 返回值为准。地面方案不要为了绕过碰撞无意设置地下高程；`elevation_m` 是相对地形高度。
- 相邻曲线保持切线连续。MCP 曲线链检查段间切线偏差不超过 5 度；连接既有轨道时还要读取既有边端切线，当前接口不会自动证明接头平顺。
- 路口、桥墩、建筑、站台、树木和其他网络都可能产生原生碰撞。设计阶段保留路口和站点净空，最终以 preview 为准。
- 闭合环线必须包含完整回程连接。不能把首尾坐标靠近、道路视觉交叉或线路工具自动闭合误当成轨道拓扑已经闭合。

站点间距不硬编码固定米数。先读取线路 prefab 的最小站距，再结合居民、就业、换乘和路口分布选择位置。站点过密会降低运行速度并增加车辆聚集；过疏则削弱步行覆盖。

## 4. 建设道路嵌入式电车轨道

1. 获取目标永久道路 edge ID，检查道路仍存在、方向和 prefab 正确，并读取当前车道。
2. 调用 `preview_road_features`，传入 1–64 个 `edge_ids` 和 `tram_tracks=true`；省略的自行车道、公共交通车道、绿化等道路选项保持原状。
3. 轮询 `get_road_operation`。只有 `preview_ready`、`can_commit=true`、无错误且费用在授权上限内时才调用 `build_road`。
4. 继续查询原操作到 `completed`，使用返回的永久道路 ID；道路升级可能替换实体，不要继续使用旧 edge ID。
5. 对每条结果道路调用 `inspect_road_lanes`，至少确认：
   - `tram_tracks=true`；
   - `tram_track_component=true`；
   - `tram_track_lane_count>0`；
   - 实时 `TrackLaneData.m_TrackTypes` 包含 Tram。
6. 回读相邻路口的连接车道或用后续线路预览验证跨路口连续性。每段道路各自有 Tram 车道，不代表路口已形成可用转向。

不支持该升级的道路会返回 `ROAD_FEATURE_UNSUPPORTED`。应更换实时支持的道路 prefab 或采用独立轨道，不要通过手改组件伪造轨道。拆除道路电车轨道使用 `tram_tracks=false`，但必须先迁移或删除依赖它的站点和线路，并取得相应拆除授权。

## 5. 建设独立轨道与接头

1. 从实时目录选择精确 Tram `track_prefab`。
2. 调用 `preview_transport_track`，传入 2–16 个点。新点使用 `x/z` 和可选 `elevation_m`；连接既有网络时优先使用精确 `node_id`，或用 `edge_id` 在目标边 8 米内分接。
3. 需要曲线时传与相邻点段一一对应的 `curves`；元素为 quadratic/cubic 控制点，直线段使用 `null`。必要时显式设置 `min_radius_m`。
4. 轮询 `get_transport_track_operation` 到 `preview_ready`，检查费用、坡度、曲率、碰撞和原生错误，再调用 `apply_transport_track_operation`。
5. 等待 `completed`，按 `created_track_ids` 逐条调用 `get_transport_track`，确认永久 prefab、类型、端点节点、曲线、高程和 owner。
6. 对接道路嵌轨、车辆段或其他独立轨道后，重新读取接头拓扑并通过线路原生寻路证明方向可用。

原生接入可能切分既有边，结果数量可多于规划段数。按完成结果回读，不要因数量变化重复补建。设施拥有的内部轨道应随设施管理，不要用轨道删除工具单独拆除。

## 6. 建设并接入车辆段

1. 用 `plan_transport_facility_site` 为已解锁 Tram Depot 搜索候选，或按返回的特殊放置模式选择候选。
2. 车辆段同时需要道路服务和电车轨道出口；为建筑完整占地、内部轨道、出入口曲线和未来升级保留空间。
3. 调用 `preview_transport_facility_placement`，轮询 `get_transport_facility_operation`，通过后再用 `apply_transport_facility_operation` 提交。
4. 回读永久车辆段、内部轨道/站点和道路绑定。用真实内部轨道端点建设支线，不以建筑中心坐标代替轨道节点。
5. 验证车辆段至主线两个必要方向的路径。只有一个方向可出库时，要确认线路与回段路径确实兼容，不能仅凭轨道共节点判定。

车辆段容量限制可投入的车辆数。新增线路不会自动增加容量；目标车辆数应结合实时车辆段容量和线路运行时间设置。

## 7. 放置道路侧电车站点

道路侧站点工具只接受带永久 Tram `TrackLane` 的道路，不接受纯独立轨道边。独立路权需要使用当前资产提供的兼容车站/设施，并按设施工作流施工。

1. 用 `list_road_stop_prefabs(transport_type="Tram")` 选择精确站点 prefab。
2. 选定已经通过第 4 节永久回读的道路 edge ID。
3. 调用 `plan_road_stop_site`，传 `stop_prefab`、`road_edge_id`、`edge_parameter`（0.05–0.95）和相对道路起终方向的 `road_side`。
4. 检查候选位于可建设人行道、远离路口和其他站点，且步行接驳合理。`left/right` 是道路曲线方向，不是屏幕左右。
5. 暂停后用完全相同的四个字段和稳定 `request_id` 调用 `preview_road_stop_placement`。
6. 轮询 `get_road_stop_operation`。只有 `preview_ready`、`can_commit=true`、无错误和警告时才调用 `apply_road_stop_operation`。
7. `completed` 后使用 `result_stop_ids` 回读，确认永久对象具有 `TransportStop`、`ConnectedRoute`、`TramStop`，且 `Attached.m_Parent` 指向目标永久道路。

无轨道路会返回 `TRAM_TRACK_REQUIRED`；人行道空间不足会返回 `ROAD_STOP_NO_BUILDABLE_SIDEWALK`。站点道路附着成功只证明物理放置，不证明某一行驶方向能够停靠；最终由完整线路预览和实际车辆验收。

## 8. 创建闭合有轨电车线路

1. 用 `list_transport_stops(transport_type="Tram")` 重新发现当前会话的永久站点，确认每个 stop ID 属于预期位置。
2. 按实际运行顺序排列站点。环线应沿连续轨道顺序绕行；往返线路需要为两个方向安排兼容站点，不能假定同一个道路侧站点自动服务反向车辆。
3. 用 `list_transport_line_prefabs` 选择精确 Tram 客运线路 prefab。
4. 调用 `preview_transport_line`，传同一条闭合线路的有序 `stop_ids`、名称和可选颜色。工具会从末站闭合回首站，但不会替你补建缺失轨道。
5. 轮询 `get_transport_line_operation`。只有原生寻路通过并进入 `preview_ready` 才调用 `apply_transport_line_operation`，且必须沿用同一 `request_id`。
6. 等待 `completed`，使用 `result_line_id` 调用 `get_transport_line`，核对运输类型、站序、路线距离、状态和车辆请求。

如果线路预览失败，先定位首个无路径站段，检查站点方向、路口连接、轨道断点、车辆段支线和首尾闭合段。不要更换 request ID 在相同断网几何上重复创建线路。

## 9. 运营设置与真实验收

线路建成后可以设置名称、编号、颜色、日夜时段、票价、目标车辆数和均匀发车系数。政策写入和车辆请求按工具要求在暂停状态执行。若没有兼容车辆段或网络不连通，`request_transport_line_vehicle` 只能产生待处理请求，不能证明车辆会生成。

在没有未完成写事务时短暂运行模拟，再暂停回读：

1. `get_transport_line`：目标车辆数、实际车辆、完整站序、候车和路线距离合理。
2. 线路航点/分段：每一相邻站段和末站回首站都有非空有效路径，不存在负数或缺失距离被误当成正常值。
3. `list_transport_vehicle_requests`：请求没有长期停留在无法调度状态。
4. `get_vehicle` / `get_vehicle_path`：电车从车辆段进入线路，有有效目标和路径，并持续移动。
5. 现场运行：车辆按正确方向停靠、上下客、离站，通过主要路口并完成至少一次闭合循环或往返。
6. 运行质量：检查拥堵、排队、车辆成团、过密站距、目标车辆数与车辆段容量；必要时调整而不是盲目增加车辆。

首次出车、单个站点成功停靠或一段路径有效，都不能替代完整循环验收。

## 10. 常见问题速查

| 现象 | 优先检查 | 处理方向 |
| --- | --- | --- |
| 道路显示轨道但站点报无轨 | 是否使用升级后的新永久 edge ID；`TramTrack`、Tram `TrackLane` 是否都存在 | 重新发现道路并回读车道；缺一项即重新做原生升级预览 |
| 相邻两段都有轨道但线路断开 | 路口连接车道、道路方向、真实公共节点 | 修复路口或轨道接头；不能以画面相交作为连接证据 |
| 弯道预览失败 | prefab 最大坡度、段长、采样半径、段间切线、障碍 | 放大弯道、平顺控制点或调整走廊；不要用多个短直角段替代曲线 |
| 车辆段建成但不出车 | 内部轨道端点、主线连接、车辆段容量、线路车辆请求 | 用永久端点重接支线并验证到线路两方向的路径 |
| 站点附着成功但线路找不到路 | 站点侧别、行驶方向、路口断点、回程闭合段 | 按站序定位首个失败分段，调整站点侧别或补齐轨道 |
| 环线末站无法回首站 | 首尾轨道没有真实连接或方向不兼容 | 先完成永久闭环，再重新预览线路；线路自动闭合不等于自动铺轨 |
| 线路有车辆但长期成团 | 站距、路口拥堵、目标车辆数、均匀发车系数 | 减少冲突、调整车辆数和 unbunching，运行后重新观察 |
| 准备移除轨道升级 | 依赖站点、线路、车辆和替代路径 | 先迁移线路与站点，确认无依赖后再授权拆除 |

## 11. 施工放行清单

- [ ] 当前城市已发现并解锁 Tram 车辆段、轨道、站点和线路 prefab。
- [ ] 线路走廊、回程/闭环、车辆段支线和全部站点已整体规划。
- [ ] 所有永久道路轨道均通过 `TramTrack` 与实时 Tram `TrackLane` 双重回读。
- [ ] 所有独立轨道按完成结果回读了 prefab、曲线、节点和高程。
- [ ] 每个交叉口和道路—独立轨道接头都形成真实可寻路连接。
- [ ] 车辆段道路接入、内部轨道和主线连接均已验证。
- [ ] 每个站点具有永久 Tram 站点组件、道路附着和步行接驳。
- [ ] 原生线路预览覆盖完整有序站序及末站回首站。
- [ ] 永久线路全部分段可寻路，实际电车完成闭合循环或完整往返。
- [ ] 已恢复原模拟速度，并记录实体 ID、operation ID、费用、未验证项和运营观察时间。
