# 铁路站区规划、续建与验收

用于客站、火车总站、货站和车辆段的联合规划与施工检查。参数以实时 MCP schema 和 prefab 为准；本清单来自奥本山站区实测，不把个别资产尺寸、设计半径或整地高度当成通用游戏规则。

接口参考：[基础设施与轨道](TRANSPORT-INFRASTRUCTURE-GUIDE.md)、[线路与调度](TRANSPORT-GUIDE.md)、[事务恢复](../../workflows/operations.md)、[建筑道路绑定](../buildings/BUILDING-GUIDE.md)。

## 1. 开工和续建基线

- 读取城市、会话、模拟速度、资金、当前镜头、已购地图格及已批准施工范围。已购土地不自动扩大用户授权范围；大半径绕行超过原范围时先更新方案。
- 换存档或重启后重新发现设施、道路、轨道、站点和外部连接。保存的 JSON、网页与实体 ID 是历史检查点，不能直接作为当前对象依据。
- 区分已完成、仅预检通过、待施工和失败项目；记录 operation ID、永久对象、费用及尚未解决的问题，避免重复建造。
- 核对实时 `tools/list` 是否包含所需字段。旧客户端工具目录可能不含新部署的 `curves`；按事务指南刷新或使用项目 MCP/CLI 同一校验入口，不能只凭 DLL 版本号认定能力可用。

## 2. 设施、道路和地形联合选址

- 明列客站、总站、货站、车辆段各自的位置、朝向、道路入口、内部轨道和外部接入端。用户要求总站横向贴路时，平面朝向与真实道路入口必须同时满足，不能只旋转网页图标。
- 建筑包围盒不是全部占地：检查附属轨道、站台、端口、升级预留和接轨曲线走廊。一个设施建成后，再对相邻设施进行原生预览；分别通过的旧预览不能证明最终组合无碰撞。
- 对基础四周、入口、站前路端点和接轨坡段采样。整地绝对高度与道路相对地形高度不可混用；整地后重新采样并回读道路实际高度。较大填挖及拆路须在已批准范围内执行，不能照搬本次 570 米平台。
- 道路跨越公路或铁路时，在施工图标注桥梁/高架/隧道、坡道范围和净空，并用原生预览验证；地图上交叉不等于有合法立交或网络连接。明确禁止穿越的道路应截断或绕行。
- 选址使用规划器返回的精确位置、朝向和道路 ID。若挪动设施或重新分段道路，重新规划和预览；不得沿用旧绑定。道路重分段会改变拓扑和对象 ID，不是无条件的碰撞修复手段。

## 3. 真正的曲线接轨

- 从永久设施的 owned tracks/节点发现外部连接端，区分外部端口和内部尽头；逐一标明哪些端口需要接通。不得凭建筑中心、包围盒或 SVG 像素猜端口。
- 使用 `preview_transport_track` 的 `curves` 控制点创建真实 quadratic/cubic 曲线。少量折线段和仅在网页绘制圆弧，都不能替代游戏内平缓接轨。
- 根据空间、速度需求及实时 prefab 限制确定设计半径并留裕量。本次采用 150 米下限；这不是所有铁路必须遵守的标准。采样最小半径不是解析证明。
- 检查新段之间及新旧轨道接头的切线、方向、坡度和连接节点。当前曲线接口不会自动验证与既有网络接头的切线偏差；调用方仍要读取既有曲线检查。反向接入或肉眼接触不能证明可寻路。
- 长曲线超过实时长度上限时，可用 de Casteljau 拆分保留形状和接头切线；不要简单折线化。每段重新检查长度、坡度、半径及原生碰撞。
- `node_id` 用于精确节点；`edge_id` 用于在当前边上切分接入。节点接入失败时可研究另一合法接点，但 `GAME_VALIDATION_ERROR` 不证明必定是节点问题，也不保证换成边接入就成功。
- 失败时保留错误与几何，按段做预览/取消诊断；只在授权且有实际用途时提交部分工程。相同失败几何不能换 request ID 盲试。
- 当前 `deploy_transit_corridor` 的轨道步骤只转发点列，未转发 `curves`/`min_radius_m`。曲线接轨应使用直接轨道接口，直到实时高层 schema 和实现均确认支持。

## 4. 永久对象验收

| 检查层 | 必须取得的证据 | 不能替代它的现象 |
| --- | --- | --- |
| 事务 | 原 operation 到达 `completed`，永久实体存在 | 请求已接受或预览通过 |
| 道路入口 | 原始 `Game.Buildings.Building.m_RoadEdge` 指向当前存在、兼容且拓扑正确的道路 | 建筑贴路或封装器返回成功 |
| 水电污水 | prefab 实际需求、对应消费者连接标志与供需回读 | 道路绑定非空 |
| 轨道几何 | 永久边、节点、所有者及实际曲线；复核半径、坡度和接头 | 预览控制点或施工图 |
| 线路 | 兼容站序、外部连接、原生线路提交及永久线路回读 | 铁轨在图上连起来 |
| 初始运营 | 实际车辆、有效路径、移动与卡住状态 | 目标车辆数或线路名称存在 |

原生提交可能拆分轨道、调整竖向控制点或合并道路。若封装器报 `completed_readback_incomplete`，先停止后续相关写入，查询原 operation 和永久建筑，不能直接重建。只有当前原始道路绑定、位置、兼容性和拓扑均已验证，且能解释旧边被合并为新边时，才记录旧/新 ID 并解除该项疑点；无法解释则保持未验收。

水电应结合消费者连接标志以及需求/满足量；无对应组件时先检查资产是否需要该网络，不能一律判定断水，也不能直接宣告已供水。有限并发回读须检查每条响应，缺失响应不等于实体不存在。

## 5. 线路与实际运营

线路 apply 必须沿用其 preview 的同一 `request_id`。读取目标车辆数的实时原生范围，不将其他线路允许的数量套用到货运线路。目标数、已生成数和车辆段容量分别报告。

没有待提交事务时，按授权恢复模拟并观察车辆生成、路径、目标、移动与卡住状态。负数路线距离按不可用/异常数据保留，不能当作物理长度；再检查分段数据及车辆实际路径，不能仅据负值推断断轨。

一辆列车开始移动只证明初始调度可用，不证明全程往返、全部站台、车辆段全容量、长期货运吞吐或盈利。未连通的补充轨道必须单列；已有其他出口成功发车也不能把它标为完成。

## 6. 竣工图和交付

用永久对象重绘实际道路、设施和曲线，标注已建/未建、失败原因、设计指标与实测指标。文件更新后重新加载网页检查，不让旧版本方案冒充竣工图。交付分开列出结构完成、初始运营验证和待观察效果；记录原速度及恢复情况。
