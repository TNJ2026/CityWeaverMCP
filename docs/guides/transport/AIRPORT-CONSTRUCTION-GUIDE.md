# 机场选址、施工与运营验收

适用于当前可见区域或指定山脚的机场建设。机场 prefab、占地、原生放置条件、升级和费用通过当前城市发现，不能把其他城市机场尺寸、朝向或整平高度直接套用。

## 1. 选址与完整方案

读取城市状态、能力及 `get_camera_view`，将“当前区域”“右边山脚”等相对描述转换为当时世界范围和地形记录。用实时交通设施目录和选址工具取得候选，检查完整机场、跑道、滑行道、停机位、航站楼、升级预留及陆侧接入，不能只检查建筑中心。

靠近山脚是位置偏好，不允许山体或其他设施侵入跑道两端起降净空。结合实时可读取的空域/限高、地形及原生预览验证；数据不完整时标记未确认，不用建筑预览通过代替全部飞行路径验收。

方案同时包含接入普通道路、货运或客运集散、步行/公交接驳，以及资产实际需要的水电污水。对称与直线优先，但入口、地形和起降方向优先于图面形式。机场旁沿山脚的道路、通往水电站的连接和上山矿区道路是独立走廊，应检查相互净空而非默认属于机场施工范围。

## 2. 道路、地形与机场建设

如需整地，记录刷子完整影响范围、目标绝对高度和施工前地形；只修改已授权范围。先完成必要陆侧道路/场地，回读坡度及水域，再重新获取机场候选。不得移动旧候选位置后保留旧道路绑定。

使用 `preview_transport_facility_placement`，仅在原生 `preview_ready`、可提交、无错误且预算内时应用；查询原 operation 到 `completed`。回读永久机场、真实道路入口、内部站点、跑道/滑行网络和启用状态。需道路的机场必须有有效兼容 `m_RoadEdge`，并分别验证设施实际需要的供能、供水与排污；道路绑定非空不证明这些系统全部工作。

升级只使用当前机场允许的模块和实时吸附候选，每次完成后重新读取站点与网络。不擅自绕过跑道/限高碰撞，也不因失败自动拆除周边建筑或扩大整地范围。

## 3. 航空线路与运营

发现真实兼容客运或货运航空站点及地图外部连接，选择实时航空线路 prefab，使用公共交通线路原生 preview/apply。航空线路不通过铺设道路、铁路或船舶航道实现，也不能以跑道建成代替航线开通。

提交线路沿用 preview 的同一 `request_id`；回读永久线路站序、类型、启用与路径。恢复模拟后依次记录飞机生成、有效目标、移动、起降、滑行、停靠和乘客/货物交换。飞机已出现不等于完整往返或吞吐达标；客运成功不证明货运升级可用。

## 4. 交付与本次案例

交付包含机场及道路永久 ID、场地实测范围、起降净空核查结果、服务连接、航空线路、实际飞机和未验收项。原生失败、未知结果或玩家手动改动后，重新发现目标，不重复创建。

本对话中“尽量靠右侧山脚”和“沿山脚连接水电站”属于项目位置与走廊要求。历史[山脚机场方案](../../../artifacts/airport-foothill-plan-20260928.json)与[机场施工进度](../../../artifacts/airport-construction-20260928-progress.json)用于追溯，规划及进度文件本身不证明机场已完成全部运营验收。无需为了编写文档重放施工。

规划按[局部卡片规则](../planning/PLANNING-MAP-GUIDE.md)展示；自动施工聚焦保留当前缩放。相关接口见[交通设施](TRANSPORT-INFRASTRUCTURE-GUIDE.md)及[线路指南](TRANSPORT-GUIDE.md)。
