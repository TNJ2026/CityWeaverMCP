# 摆渡站与渡轮线路规划、施工及验收

本指南覆盖城市内部摆渡站、陆侧接驳、水上通道、客运渡轮线路和实际派船。先检查当前城市能力及资产，精确 prefab、费用、宽度、水深和净空以实时数据及原生预览为准。渡轮客运使用公共交通线路工具，不使用捕鱼或油轮的 WorkRoute 工具。

## 1. 建设顺序与默认规则

整体规划 → 陆侧道路及必要设施 → 摆渡站建成 → 回读自带泊位和航道 → 补建接驳航道 → 创建完整站序 → 永久寻路回读 → 派船及载客往返验收。

- 先勘察完整水路与两岸接驳可行性，再施工；**先放站点建筑，再连接其自带航道与客运线路**，避免预先铺设的通道与建筑生成的网络重叠。
- 站点、附属设施和新增通道避开既有码头、平台及通航走廊的完整占地；需要连接时用永久节点明确接入，不以重叠代替连接。
- 条件允许时优先对称、直线和平行布置；非直线连接采用平滑曲线，岸线、站点朝向、船舶转弯及净空优先。
- 新增小岛站点时先读取既有站点、线路和容量，再明确是增加独立线路还是修改原线站序。保留其他线路，不擅自删除或改道。
- 不因水路受阻自动整平、疏浚、填海、缩窄航道或改造桥梁；需要地形或既有网络调整时单独明确范围。

## 2. 勘察与选址

1. 调用 `get_game_status`、`get_query_capabilities`，记录会话和原模拟速度。查询实时渡轮设施、线路、船型及兼容水上网络；未加载所需资产时报告缺失。
2. 通过 `list_transport_facility_prefabs`、`list_transport_line_prefabs` 和 `list_transport_stops` 发现可用设施与既有站点。历史实例为 `FerryStop01`、`Integrated Ferry Stop`、`Passenger Ferry Line`；不能跨版本硬编码这些名称。
3. 勘察两岸实际道路、步行可达性、岸线、水深、桥梁、平台、既有航道及船舶路径。小站与总站的放置模式由 prefab 决定，不把所有站点都按相同岸线规则放置。
4. 用 `plan_transport_facility_site` 取得候选，检查站体、自带网络、泊位回转和陆侧出入口空间。候选不是施工许可，必须通过原生预览。
5. 如需先铺接岸道路，完成后重新选址，传回候选原有位置、朝向及绑定 ID；不能移动候选后继续使用旧道路绑定。

需要道路的设施必须接入兼容普通道路，核验 `Game.Buildings.Building.m_RoadEdge` 非空且指向当前有效道路；贴近道路或操作完成不能替代绑定证明。另查供能及乘客步行换乘，不将高速公路视作普通市政道路。

## 3. 站点建设与永久回读

暂停城市后，使用 `preview_transport_facility_placement`，轮询 `get_transport_facility_operation`。仅 `preview_ready`、`can_commit=true`、无原生错误且费用在范围内时提交；提交参数和预算字段以实时 schema 为准。

查询原操作到 `completed` 后，用 `get_transport_facility` 和实体组件回读：

- 正确位置、朝向、道路绑定及设施归属。
- 真实永久站点 ID、运输类型及客运兼容性。
- 设施与停靠点启用状态。
- 自带航道的 owner、曲线、完整宽度及端点。

`owned_tracks=[]` 不能证明设施没有自带航道；使用 `list_waterways`、`get_waterway` 及 `SubNet` 单独发现。新增升级后也要重新读取永久泊位与网络。

## 4. 接驳航道与桥下通航

通过 `list_waterway_prefabs` 选择与当前渡轮兼容的网络，不能仅按名称或最窄宽度选择。两端使用真实永久 `node_id`，或在工具允许的范围内以 `edge_id` 分接既有边；不使用建筑中心或泊位位置代替航道端点。

使用 `preview_waterway` 建设连接，转弯传 `curves` 并保持切线连续。检查整条曲线及航道全宽的水深、岸边障碍和转弯空间；分段满足实时最大长度与曲率条件。预览通过后以明确费用上限提交，回读原操作 `completed` 及全部永久新边和端点。

桥位同时检查水面与桥底的通航净空、桥墩占地、桥下有效通道以及原生寻路。桥面高度、桥跨总长或视觉上水面连续，都不能单独证明船能通过。开合桥还须检查实际兼容通航条件；不把其他桥型或历史成功桥位的参数当作统一标准。

异宽接头必须单独验证。原生接入可能分割旧边，按返回的永久对象核对拓扑，不能按对象数量补建重复通道。水路已连通仍须另建客运线路。

## 5. 创建或调整渡轮线路

1. 用 `list_transport_stops` 重新发现兼容的永久渡轮客运站点，确认每个 ID 属于预期位置。
2. 选择实时渡轮线路 prefab，按实际行驶顺序提供 `stop_ids`。使用 `preview_transport_line` 创建；增删站或重排既有线路使用 `preview_transport_line_stops`，先记录完整旧站序。
3. 轮询 `get_transport_line_operation`，核对原生寻路、站序、警告与错误。线路工具负责末站回首站的闭合验证，不负责补建缺失航道。
4. 只对通过的预览调用 `apply_transport_line_operation`，**沿用 preview 的同一 `request_id`**。等待原操作 `completed`，回读 `result_line_id`。
5. 用 `get_transport_line` 核对类型、站序、启用、距离和车辆请求；检查泊位 `RouteLane`、去程与返程 `PathElement` / 路径状态。负数或缺失距离不能作为有效里程。

预览失败时定位首个无路径站段，检查泊位绑定、航道断点、方向、水深与桥位障碍。不能通过更换请求 ID 在相同断网几何上反复创建线路，也不能误用客运邮轮、货船或油轮工作线路替代渡轮。

## 6. 派船、载客与最终验收

保持原有运营政策，按需要设置线路名称、日夜时段、票价及车辆目标。目标车辆数量受实时原生范围和供车能力约束；车辆请求被接受不等于已经生成船只，不凭空要求所有渡轮资产具有相同车辆段结构。

无待处理事务时恢复模拟，按以下层次记录结果：

| 层次 | 验收证据 |
|---|---|
| 建筑完成 | 永久站点、道路与必要服务接入、站点启用、步行接驳 |
| 航道完成 | 永久接驳边及节点真实连通、全宽水深和桥下通航检查 |
| 线路完成 | 正确站序、原操作 completed、永久线路和全部往返路径有效 |
| 已派船 | 线路出现实际兼容渡轮，车辆路径有效并持续移动 |
| 载客运营 | 实船到站、上下客、离站并完成一次完整往返或循环 |

应观察多个时刻的位置、目标和路径，而非用单个 `EnRoute` 状态认定成功。首次派船可能还在前往首站的途中，不能当作已经完成站间航行。未观察到载客往返时，明确报告“已派船，完整载客往返未验证”。

## 7. 断点恢复与规划展示

- 玩家手动拆除、移动站点或修改道路/航道后，重读受影响永久对象，废弃旧 ID 与候选；只继续已授权的剩余工作。
- `TOOL_BUSY` 可先以 normal 推进 200–500 ms 再暂停，仍忙时请玩家回到默认工具；`USER_CHANGED_TOOL` 时查原操作并停止依赖施工，尊重玩家操作。
- 失败、超时或 `outcome_unknown` 时查询原事务及永久对象，不能换 ID 盲目重建。已完成部分保留，未完成部分如实记录。
- 局部规划卡片以本次区域和必要连接端点为初始视野；MCP App 卡片已显示时，不重复打开规划图网页。
- 自动聚焦施工位置时保持玩家当前缩放值，玩家镜头输入优先；无待处理预览且用户未要求暂停时恢复原模拟速度。

## 8. 历史实测与边界

2026-09-28 的[小岛摆渡施工记录](../../../artifacts/island-ferry-construction-20260928.json)验证了“小岛东岸摆渡站”的永久道路绑定、连续水路及“小岛—湖湾镇摆渡线”的非空往返路径。线路为两个站点，总路径约 7,585.21 米；观察到 3 艘 `FerryPassenger01`，多时刻位置显示持续移动。

该记录明确说明未观察完整载客往返。船只当时仍在前往站点的途中，不能据此宣称靠泊、上下客或长期运力已经验收。其 29,240 费用属于该次小岛扩建，不是两岸系统通用造价。此前两岸建设记录见[摆渡施工档案](../../../artifacts/ferry-construction-20260928.json)。历史 ID、坐标、票价和车辆数仅用于复核，新工程重新发现。
