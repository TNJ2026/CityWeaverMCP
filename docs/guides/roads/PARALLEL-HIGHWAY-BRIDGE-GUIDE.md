# 并列单向高速桥与环岛接入

用于两幅单向高速桥跨水连接既有高速与环岛道路。吊桥、开合桥及普通高架桥分别按实时 prefab 的结构和通航能力检查，不能以名称相近互相替代。本次“两条单向三车道”是项目参数，不是默认桥型或车道数。

## 规划与原生施工

1. 读取既有高速和环岛道路的永久节点、曲线、真实行驶方向与车道，明确两岸来向和去向。两幅桥通常承担相反方向，必须分别画出箭头，不能机械复制同一方向。
2. 调查整条水域的水面、海床、航道全宽、船舶实际路径、桥墩与桥塔空间。两幅桥中心距按实际宽度和结构净空设计；直线段平行，曲线段尽量等距伴行，不能只保证两端间距。
3. 先确定通航跨、引桥、坡度和两岸连接。优先直线跨越，转弯用连续平滑曲线；不得把桥跨长度当成桥墩之间的有效净宽。
4. 分别使用当前道路工具生成原生预览，校验桥型、车道、结构、坡度、碰撞和费用。第一幅完成后回读再预览第二幅，不能同时通过的旧预览替代组合后的净空检查。
5. 提交后查询原操作到 `completed`，按新永久 ID 回读桥面高程、桥墩/桥塔、端点、车道和方向。检查高速驶入、跨桥、到环岛及反向返回的完整有向路径。

道路 `elevation_m` 为相对地形高度；桥底净空还取决于结构与水面，不能混用绝对桥面高度、海床高度和船舶要求。原生 `waterway_crossings_verified` 只证明工具所观察到的交叉拓扑回读；普通跨越未生成共享节点时，不能据此认定不通航或已通航。还需实际路径及船舶通过验证，详见[开合桥跨航道](ROAD-GUIDE.md#开合桥跨航道)。

## 局部航道改宽

优先调整桥位或兼容桥型；确需改宽既有航道时，单独记录影响段、原宽、目标宽、两端过渡及依赖线路，并取得该改动授权。更窄不代表船型兼容，必须重新进行全宽水深、桥位碰撞和原生寻路检查。

本对话曾明确允许将桥位附近约 886 米的一段航道从 410 米改为 110 米。此授权仅属于该次桥位施工，不得用于其他航道，也不能作为所有桥梁的标准净宽。是否完成与可通船分别依据原操作、永久对象及运行证据，不从授权消息推断。

## 巨型环岛与桥头路口

用户要求升级为巨型环岛时，先区分 `preview_intersection_roundabout` 的原生单节点环岛与 `preview_road_ring` 的多节点道路圆环。根据实时尺寸上限及周边空间选择，并说明采用哪种结构；不能只改名称就称巨型环岛。

保留全部必要进口和出口，核对城市行车侧与环流方向。各支路顺向汇入、驶出，避免桥头短距离交叉和排队溢出桥面。道路升级/拆分后重读接入节点与车道。检查环上信号控制和行人接驳，不默认删除所有斑马线；修改应依据实际冲突并保留可达路径。

## 验收

- 两幅桥各自满足要求的车道、方向、平行关系、结构及引桥坡度。
- 既有高速与环岛之间双向行程实际可达，不能仅凭圆环几何闭合。
- 航道改动与授权范围一致，所有受影响航段路径有效。
- 实际船舶通过桥位才证明本次通航运行；开合桥动画及长期交通容量若未观察，另列未验收。
- 玩家拆除障碍后重新勘察；失败或未知操作先查原日志，不盲目重建。规划只显示相关桥位及连接范围，自动聚焦保持当前缩放。
