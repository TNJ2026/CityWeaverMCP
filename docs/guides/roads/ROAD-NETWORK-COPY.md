# 街区路网复制

`preview_road_network_copy` 把已有路网按锚点整体平移、旋转到另一块地。分支、闭环和混合道路类型都可选择，无须按路线排列。1.28.0 起支持显式指定既有道路进行接驳和重叠路段复用。1.36.88 起支持沿指定道路轴线镜像。

镜像参数为 `mirror_axis: {"start":{"x":0,"z":-100},"end":{"x":0,"z":100}}`，两点定义无限延伸的世界坐标轴线，间距至少 1 米。先镜像，再旋转和平移，`source_origin` 仍映射到 `target_origin`。纯镜像时将两个 origin 都设为轴线上同一点，旋转设为 0。曲线和真实路口一同变换，左右侧升级标记互换，有向道路起终点顺序保留。该操作镜像路网几何，不翻转道路资产模型本身。返回 `copy_mirror_axis` 可核对实际轴线；未启用时为 null。

先暂停城市并切回默认选择工具，再创建预览：

```json
{
  "request_id": "copy-block-preview-001",
  "bounds": { "min_x": -1200, "min_z": -800, "max_x": -600, "max_z": -200 },
  "source_origin": { "x": -900, "z": -500 },
  "target_origin": { "x": 1800, "z": 1000 },
  "rotation_degrees": 0,
  "height_offset_m": 0
}
```

1.36.86 起，也可用 `edge_ids`（1–1024 个唯一永久道路 ID）替代 `bounds`，两者必须二选一。框选最多 2048 条道路，仅纳入四个贝塞尔控制点均位于框内的完整道路；跨越边界的道路不会被截取。查看返回的 `segments[].source_edge_id` 确认选择结果。超过上限整次拒绝，不会悄悄只复制部分道路。

传输上限同步扩大为请求 128 KiB、响应 8 MiB。桥接端点会公布实际容量，客户端连接旧模组时仍遵循旧上限。更新模组后，持久运行的 MCP 服务需重启或重新连接以刷新 `edge_ids` 工具参数上限。容量扩展只放宽选择规模；自动分段导致的段数差异、接驳回读校验仍按原有规则处理，不代表所有大型路网都已通过实机施工验证。

`source_origin` 映射到 `target_origin`。旋转采用 Unity 正 Y 轴方向：90° 将向东的方向转向负 Z。1.36.87 起，独立复制和接驳复制均以真实 `Node` 位置及原中心线切线重建原生道路，避免把路口边缘的裁切点当成节点。节点及曲线控制点高度统一加上 `height_offset_m`。工具不缩放、不吸附网格、不按新地形变形；目标地块高度不同时，可显式设置高度差。道路与目标地形的净空超出预制件支持范围时会拒绝预览。

轮询 `get_road_operation`，等待 `preview_ready` 后调用 `build_road`，传入新的 `request_id`、`operation_id` 和 `max_cost`。也可调用 `cancel_road_preview` 取消。完成后需同时确认 `state: completed` 与 `copy_verified: true`；`created_road_ids` 是新复制的道路。独立复制可通过 `preview_road_undo` 创建整组拆除预览，再提交撤销。

复制保留真实路口位置、有向中心线走向、道路预制件及边上的升级标记，包括单行方向、分区侧开关和适用的车道、装饰选项。1.36.87 起，校验每条源道路对应的完整有向路径：游戏可将一条长道路拆成多段，但新增节点必须只连接该路径的前后两段，且不能合并原有路口或额外接入其他道路。原节点位置容差 0.35 米；每段中心线须位于原生重建中心线 0.5 米以内，并检查路口端部裁切和内部连续性。每个新道路实体必须恰好被一条源路径覆盖。路口边缘由原生系统重新裁切，因而不要求渲染曲线的四个控制点或最终段数完全相同。

施工后不一致仍会返回 `outcome_unknown`，不要自动重试施工。1.36.87 同时处理原生施工删除临时保留段、改为原地更新旧道路的情况：会读取实际存活的完整通道，再核对覆盖范围、节点身份、预制件和升级标记，不能仅因为临时实体消失而认定断路。

此工具仅复制路网，不复制建筑、已占用分区、道路名称、自定义树种及路口专属信号灯/环岛等控制设置。建筑所属道路不支持独立复制。现有道路和建筑的删除或替换会阻止预览提交。

## 接入已有主干道

在请求中加入 `connection_edge_ids`：1–16 条明确允许接驳的永久道路 ID，不能与源路网重叠或重复。不设置时仍为严格独立复制，不会自动寻找或修改周围道路。`connection_tolerance_m` 为源节点变换后到目标道路的水平吸附上限，0.25–32 米，默认 16 米；垂直高度差必须在 1 米以内。

接驳模式以源路网的真实 `Node` 位置重建原生 `NetCourse`。游戏中部分 `Curve` 端点位于路口边缘，不能把它们当成独立节点。工具用原生切线拟合还原到真实节点，并将选中的连接节点吸附到指定目标道路；其余节点不作水平移动。内部连接由原生工具拆分目标道路。两个不同源节点若会吸附成同一节点则拒绝。

1.28.2 起，根据接入道路和目标道路的半宽总和加 4 米（至少 8 米）确定端点附近的路口预留距离。在此范围内优先复用已有节点，且源节点到该已有节点的实际距离必须在 `connection_tolerance_m` 内；否则返回 `ROAD_COPY_CONNECTION_TOO_CLOSE`，不会生成可能推动原路口的过短分段。例如 16 米道路接入 40 米主干道时，预留距离为 32 米；接入点投影距原路口约 16 米、源点距原路口约 20 米时，可显式给 24 米容差复用原路口，而不是拆出一条 16 米长的主路。这一接驳调整会反映在 `copy_connections` 中。

1.28.3 修正上述规则对普通主路分段节点的处理：如果端点只连接两段同预制件、同升级标记的独立永久道路，接驳保留原投影位置，不再为了避开旧分段节点而向其吸附（距端点 0.25 米内仍复用）。三岔路口、十字路口、建筑所属网络等继续执行保守距离限制。目标主路两个端点的临时节点在 `NodeReductionSystem` 执行期间添加临时 `Fixed`，阻止游戏重新分配相邻分段长度；该组件在同阶段的清理系统中移除，并在工具读取预览或提交之前再次清理。永久道路及永久节点不添加组件，不改变全局原生系统开关；完整曲线、原端点身份和相邻道路替换检查保持启用。此修复不保证所有近距离路口都能通过原生碰撞及几何检查。

如果源路段的两端均落在同一条指定主干道上，且道路预制件、方向、升级标记及走向兼容，则复用这一段主干道，不重复铺设。被复用路段的两端都必须连接新复制道路，否则会拒绝无法实际生成的路口。道路升级不兼容、地形净空不合法、建筑拆除或未指定道路被替换，仍会阻止施工。

接驳模式不再承诺每个路口控制点严格刚性复制：允许上述节点吸附和原生路口裁剪。节点回读容差为 0.35 米，曲线须位于拟合路线 0.5 米内，方向保持一致，端点裁剪范围按源路口裁剪量及吸附位移设限。预览与永久回读同时验证目标主干道的全部替换分段：预制件、升级与走向须保留，原起终节点之间必须形成无缺口、无重复覆盖且共享真实节点的连续路径。

返回结果中：

- `copy_geometry_mode`：`rigid` 为默认独立模式，`native_junctions` 为接驳模式。
- `copy_source_segment_count`：原选择道路总数；`segment_count` 是计划提交的道路曲线数，可能因复用而减少。原生自动分段时，`created_road_ids` 数量可大于 `segment_count`，以完整路径校验结果为准。
- `copy_connections`：源节点、目标道路/节点、吸附位置、拆分参数及实际移动距离。
- `copy_reused_segments`：复用主干道的源路段。
- `created_road_ids`：新复制的道路，不包含原主干道的拆分保留段。
- `split_remnant_road_ids`：接驳产生的原路保留分段，包括被复用部分；不能当成新建道路拆除。
- `copy_validation_failure` / `copy_validation_diagnostics`：校验失败的阶段与清理前保存的原生临时道路、节点、曲线和升级标记。1.28.1 起提供，最多保存 128 段预览道路，便于区分匹配差异与真实断路。

接驳复制暂不提供自动撤销，`preview_road_undo` 会明确拒绝。不能通过拆除所有返回道路来假装恢复原路拓扑。任何 `outcome_unknown` 均须停止，查询原事务及永久道路，不更换请求 ID 重试。
