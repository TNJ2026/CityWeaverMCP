# 爬山公路规划、施工与验收

本指南用于沿山坡爬升、绕行山体及盘山急弯道路。基础事务和手工曲线接口见 [道路指南](ROAD-GUIDE.md)，局部整坡见 [地形指南](../areas/TERRAIN-GUIDE.md)。

道路延伸至山顶后建设煤矿、矿石设施及扩展开采区，按[山地采矿指南](../buildings/MOUNTAIN-MINING-GUIDE.md)继续，分别验证场地、主楼、区域和生产，不以道路完成代替投产。

自动规划使用 `preview_road_autoroute`，读取实时地形、水深、建筑和永久道路。它提供地面道路候选，最终放置、碰撞和费用由游戏原生预览判断；不会自动设计跨谷桥梁、隧道或保证找到所有可行路线。

## 1. 勘察与选线

1. 查询当前城市与工具能力，确认加载的是包含所需功能的模组。使用 `list_road_prefabs` 选择当前已解锁的准确道路名称，核对宽度和行驶方向。
2. 用规划地图读取目标区域内的道路、建筑和水域，以 `sample_terrain` 采样起终点、山腰、拟定急弯平台及道路两侧。记录绝对地形高度，避免只看端点高差。
3. 优先沿山腰安排爬升走廊，为回头弯留出平面空间。直线最短不代表坡度可行；绕行空间不足时，应移动中间控制区或重新选线。
4. 接入既有路网时，读取当前节点或路段 ID、世界坐标和高度。端点显式提供 `node_id` 或 `edge_id`，不能同时提供二者；请求坐标须在目标节点或曲线 8 米以内。仅坐标相邻不证明道路相连。
5. 记录施工范围、预计占用土地、受影响建筑及预算。需要切坡、填谷或改水边地形时，将这些变化纳入施工方案；预览道路通过不代表土方影响已经验收。

高差除以水平路线长度可用于估算平均坡度，但不能替代逐段和曲线坡度检查。道路的实际坡度上限来自所选 prefab，不使用统一的“所有山路最大坡度”。

## 2. 自动规划参数

| 参数 | 当前范围或默认值 | 山路使用方式 |
| --- | --- | --- |
| `road_prefab` | 精确、已解锁的道路名称 | 根据交通需求和可用走廊选择宽度；较窄道路也须满足通行需求 |
| `start` / `end` | 世界坐标 `x`、`z`，可带接入 ID | 自动路线两端的水平直线距离须为 16–2048 米；这不是绕行后的总长度上限 |
| `zoning_alignment` | 默认 `true` | 山坡曲线路线显式设为 `false`；默认模式只走正交方向，并要求既有接入点对齐网格 |
| `strategy` | `shortest`、`balanced`、`gentle`；默认 `balanced` | 可先尝试 `gentle`，其坡度余量、坡度和转弯惩罚最大；它也可能比其他策略更容易返回无可行路线 |
| `grid_size_m` | 16–48 米；默认 24 米 | 24 米作为初始尝试；减小可提高空间分辨率但增加搜索规模，增大可能遗漏狭窄通道 |
| `max_detour_m` | 64–512 米；默认 192 米 | 扩展起终点包围矩形四周的搜索范围，不是允许增加的路线长度 |
| `request_id` | 本次预览的幂等键 | 同一请求重试保持原值；调整参数形成新方案前，先结束旧预览 |

启用 `zoning_alignment=true` 时，网格尺寸还必须是 8 米的整数倍，新端点会吸附到网格。山路使用 `false` 不会自动禁用沿路分区，也不保证整齐分区；分区设置与验收另按道路指南执行。

当前实现还有以下限制：

- 搜索网格不超过 16000 个单元，最终路线不超过 32 段。
- 简化折线每段水平长度不超过 248 米；输出曲线仍须满足单段 16–256 米长度校验。
- 搜索和简化对转向进行约 90° 的限制（点积比较含数值容差）。回头弯需要分布在多个转向与足够空间上，不能靠一个折点完成锐角折返。
- 曲线模式复用相邻路点的平面切线，从宽到窄尝试控制柄。半径门槛为 `max(8 米, 道路宽度 × 0.75)`，这是规划器筛选值，不是游戏对所有道路的统一标准。
- 半径采用包含两端的 257 个参数采样点，根据曲线导数计算；坡度、水域和障碍也有独立采样检查。这些是有限采样，不能视为全连续几何或道路全宽的安全证明。
- 规划器为端点附近的道路接入保留避障豁免，原生预览仍须检查当地实际碰撞和连接。

## 3. 预览与施工

先暂停城市、切回默认选择工具，并结束其他未完成预览。下面仅为参数模板，坐标和 prefab 占位符必须替换为本次勘察结果；示例不包含既有路网接入 ID。

```json
{
  "request_id": "mountain-road-section-a-preview-v1",
  "road_prefab": "替换为已查询到的准确道路名称",
  "start": { "x": 1000, "z": 1000 },
  "end": { "x": 1400, "z": 1200 },
  "strategy": "gentle",
  "grid_size_m": 24,
  "max_detour_m": 192,
  "zoning_alignment": false
}
```

1. 将参数传给 `preview_road_autoroute`，记录返回的 `operation_id` 和请求参数。
2. 轮询 `get_road_operation`。只有 `preview_ready`、`can_commit=true` 且没有阻断错误时才进入提交；检查费用、实际几何、原生碰撞与拆迁结果。
3. 核对急弯平台、坡面切填、两端连接和临近道路。规划器找到候选不等于原生预览通过；预览通过也不等于已经施工。
4. 在已授权的路线和预算范围内，调用 `build_road`，传入原 `operation_id`、稳定的提交 `request_id` 和足够的 `max_cost`。
5. 继续查询至 `completed`，记录 `created_road_ids`。取消未提交方案使用 `cancel_road_preview`，不要同时保留多个道路预览。

较长山路可在可施工的山腰平台处分阶段建设。当前自动接口只有起终点，没有中途必经点参数。需要控制经过某个平台时，应分段规划，并在前一段建成后重新读取永久节点，显式连接下一段。施工前还要预留后续段的转向空间；分段不会自动保证跨事务接缝平顺。

## 4. 失败后的调整顺序

| 返回或现象 | 检查与处理 |
| --- | --- |
| `ROUTE_ENDPOINT_IN_WATER` | 重新选择干燥端点并检查沿途水域；自动地面规划不承担跨水桥梁设计 |
| `NO_AUTOROUTE` | 检查局部坡度、障碍和接入位置，扩大合理的绕行走廊或移动端点；该结果不证明地图上不存在其他路线 |
| `ROUTE_SEARCH_TOO_LARGE` | 减小搜索范围、适当增大网格，或分阶段建设；不要同时扩大绕行范围和提高网格精度 |
| `ROUTE_TOO_COMPLEX` | 在合适平台分段，或适当增大网格后重新检查细节；不能只删除弯点来压缩段数 |
| `ROUTE_SEGMENT_TOO_SHORT` | 调整端点或平台位置，检查与网格的关系，避免短接缝落在急弯处 |
| `NO_AUTOROUTE_CURVE`、`STEEP_SLOPE`、原生急弯/坡度错误 | 扩大转弯平台、延长爬升路线、重新选取接入方向；原生错误也可能以其他代码返回，应读取完整操作结果 |
| 原生碰撞或不允许的拆迁 | 检查道路全宽、相邻路基与建筑入口，重新选线或另行规划必要改造 |
| `outcome_unknown` 或提交后通信超时 | 查询原操作与永久道路，核实已落地部分；不得换新请求 ID 重建同一路线 |

`gentle` 的搜索坡度阈值为 prefab 上限的 70%，`balanced` 为 80%，`shortest` 为 90%；最终曲线仍单独验证。切换策略可能找到另一候选，但不应把减少安全余量当作修复急弯或地形问题的固定步骤。

参数变化前取消尚未提交的预览。城市重载后会话操作记录及实体 ID 可能失效，必须重新查询现状。

## 5. 必要时进行局部整坡

先尝试合理选线，再决定是否修改地形。需要整坡时，记录原地形采样、刷子影响范围、既有道路和建筑，保留施工前存档。地形接口没有可精确还原原地形的原生撤销日志。

使用 `preview_terrain` → `apply_terrain` → `get_terrain_operation` 的独立流程；具体参数见 [地形指南](../areas/TERRAIN-GUIDE.md)。`slope` 至少需要两个路径点，`start_height_m` 和 `target_height_m` 是绝对高度。多段坡面按路径累计水平长度插值高度，并分别生成刷子段；急弯相邻刷子可能重叠，不能将它当作精确道路设计面。

地形预览是参数检查与基线采样，不是完整的临时变形展示。`completed` 和 `change_observed` 也不保证整个坡面达到目标高度。提交后重新采样道路中心及两侧，检查水深、边坡和既有设施，再重新生成道路预览。局部山路整坡不需要整图平整或清空水体。

## 6. 永久施工与通行验收

- **事务**：每阶段 `completed`，结果道路 ID 已记录；没有未处理的 `outcome_unknown`。
- **连接**：读取永久边和节点，核对相邻段共享节点、接入路网及节点的连接边引用。不能用画面重叠判断连接。
- **车道**：用 `inspect_road_lanes` 检查实际车道与行驶方向，特别是单向道路、急弯和分阶段接缝。
- **地形**：检查道路全宽与周边坡面，确认没有异常悬空、埋入、过量切填或积水；原生道路可能切填中间地形，端点高度正确不能替代这项检查。
- **运行**：在已授权的模拟运行范围内观察车辆实际经过山脚接入口、关键急弯与山顶接出口。需要双向服务时分别确认两个方向；没有车辆经过时只能记录为施工已完成、通行待验证。

保存路线参数、预览与提交操作 ID、永久道路 ID、费用、运行观察和未验证项目。截图可辅助检查外观，不能替代永久网络及实际通行证据。

## 7. 当前验证状态

截至 2026-09-27，急弯合并前后转向校验、曲线端部半径检查已修复；自动寻路回归测试覆盖危险合并的两个方向、合法合并、曲线两端急弯、退化端点、宽弯、直线、端点障碍及既有绕水和端点简化场景。完整构建通过，产物暂存于仓库，尚未部署到游戏。

本轮没有完成新版模组的游戏内山地施工与实车验收。上述测试和构建结果不能写成“盘山公路已实测可通行”；后续实测应单独记录存档、游戏/模组版本、路线、操作 ID 和运行证据。
