# 山地煤矿与矿石开采施工指南

用于上山道路、局部场地整理、煤炭与矿石设施、开采区域扩展及投产验收。煤矿、矿石厂的精确 prefab、资源要求、区域限制和费用从当前城市发现；“道路两侧各一座”是本次用户指定布局，不是所有矿区的固定配置。

## 勘察与施工顺序

1. 读取城市状态、当前镜头世界范围、地形、资源图层和已有道路。用户要求建设到屏幕中间时，记录该次镜头的目标坐标；不能从旧截图或后续移动的镜头推断同一位置。
2. 先设计完整上山路线、场地、道路入口、开采区与货运通道。优先对称布置两侧建筑，但资源覆盖、坡度、入口和区域边界优先于形式对称。
3. 上山道路采用连续平滑曲线，既有山脚道路端点与新段切线平顺。逐段校核坡度、曲率及净空，不能以平均坡度合格替代全线检查。具体方法见[山路指南](../roads/MOUNTAIN-ROAD-GUIDE.md)。
4. 需要整平时明确场地边界、刷子影响范围和目标绝对高度，先保存采样基线。只处理已授权范围；道路下方或场地外的额外刷宽也应计入影响，不将“可改地形”理解为任意填挖。
5. 整地完成后重新采样并重新获取建筑候选，不沿用整地前位置与道路绑定。道路永久建成后，分别预览两侧建筑；先建成的一侧可能改变另一侧碰撞条件。
6. 建筑与道路验收通过后，再扩展各自开采区，最后运行模拟检查生产及物流。

## 建筑与开采区

用 `list_building_prefabs(kind="specialized_industry")` 发现声明采集区的产业主楼，通过原生预览、提交与永久回读完成建设。`Placeholder` 名称和零费用不代表无须验收。道路绑定必须指向有效兼容普通道路；有供能需求的设施还需分别核验消费者连接及满足量。

用 `list_building_areas` 读取该主楼允许的精确区域 prefab、现有边界、资源与限制。不得用行政区或 zoning 代替开采区，也不能把一座矿场的区域绑定到另一座主楼。

“扩大到最大”指在当前原生限制、建设范围、资源、碰撞及接入条件内寻找尽可能大的有效边界：

- 先读取现有边界和可用限制，保护道路、建筑、另一矿场、通道及未授权用地。
- 以资源分布为依据生成候选；采用 `preview_building_area` 校验完整简单多边形，不能为了增加面积跨越禁止范围。
- 比较候选面积、资源覆盖与原生拒绝原因，选择已验证的最大候选。若未证明全局最优，应报告“当前约束下已验证的最大候选”，不能仅凭一次预览称绝对最大。
- 提交后回读永久 owner、边界、面积与资源统计，分别记录煤炭和矿石区域；不把一侧成功推及另一侧。

## 搬移失败与残留清理

搬移或重建失败后查询原 operation、新旧永久建筑、附属区域及道路绑定，区分真正空残留与仍有生产/网络依赖的设施。不按名称、距离或“旧址”自动批量删除。已授权清理时列明唯一目标及附属影响，走原生拆除预览和永久回读；结果未知先查询，不重复搬移或拆除。

玩家手动拆除后重新发现现场，旧实体 ID 和候选作废。施工遇到工具占用按[事务恢复](../../workflows/operations.md)处理，已建部分保留。

## 验收与案例边界

交付分别列出道路永久边及方向、场地实测高度、两个主楼及有效道路入口、各自区域面积和资源、消费者连接、货车可达、生产/库存变化，以及残留清理结果。暂停状态下库存不变不能证明未投产，首次出车也不能证明长期吞吐。

本对话要求了山顶道路两侧煤矿与矿石、扩区及旧址残留清理。本指南固化其处理流程；未在本轮重新读取对应游戏对象，不将对话中的“继续”或规划文件当作当前存档已投产证据。

区域事务详见[建筑附属区域](BUILDING-AREA-GUIDE.md)，地形影响见[地形指南](../areas/TERRAIN-GUIDE.md)。
