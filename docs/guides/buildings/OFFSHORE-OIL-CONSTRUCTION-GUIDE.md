# 海上油井规划、施工与验收

本指南用于 CityWeaverMCP 建造海上石油设施，覆盖石油港口主体、延长码头、顺应塔与半潜式平台、石油管道、接驳航道和油轮作业线路。按当前城市的工具 schema、prefab、原生预览和永久回读执行；文中的历史数值不能直接作为其他存档的施工参数。

## 1. 默认规则

- **石油码头默认至少延长 320 米，达到后仍可继续延长。** 用户指定长度超过 320 米时执行指定长度。从主体原有码头的水侧末端计算新增长度，不包含主体原段；玩家手动延长计入已完成长度。明确要求“再延长”时，从当前末端增加指定长度。先测量永久边链，再确定本次增量；用户明确不再延长时保留现状。
- **平台直接放置于合适水域，不为平台填出陆地。** 顺应塔和半潜式分别读取原生浮动放置参数，不能套用普通陆地建筑的高度或整平流程。
- **平台本体及自带航道避开码头、码头左右两侧航道，以及其他已经存在的航线和航道。** 按实际曲线、全宽和转弯净空检查，不能只避让中心点、航点连线或建筑外框。不得通过放置平台自动合并、覆盖既有通航走廊。
- **先建平台，再接驳。** 建筑完成后重新发现自带航道、工作停靠点及管道端口，用永久节点连接，不用重叠表示接通。
- **石油管道默认不设置高度。** 使用实时兼容端口，由原生管道工具处理高度与吸附，不指定固定埋深或水面高度。
- 几何条件允许时优先对称、直线与平行布置；需要转弯时用平滑多段曲线。避让、安全净空和原生连接条件优先。

码头 Pathway、船舶 Waterway、油轮 WorkRoute 和石油资源管道是四类独立对象，必须分别建设和验收。

## 2. 开工勘察

1. 调用 `get_game_status` 和 `get_query_capabilities`，确认城市已加载，记录会话、原模拟速度和现有设施。实体 ID 只在当前城市会话有效。
2. 发现石油产业主体及兼容升级 prefab。历史实测资产为 `Offshore Oil Industry Placeholder`、顺应塔 `ExtractorOffshoreOilRig01`、半潜式 `ExtractorOffshoreOilRig02`；必须在当前城市重新确认名称、解锁、owner、放置范围、占地和资源要求。
3. 用 `list_pier_pathways` 读取码头永久边链、末端及延长长度；用 `list_waterways` / `get_waterway` 和建筑 `SubNet` 读取两侧航道、实际曲线、宽度、端点与归属。
4. 查询附近客运、货运和工作船线路，读取实际航段路径。避让范围同时包括物理航道全宽、船舶路径和平台自带航道；无法取得实际路径时，不声明已通过避让检查。
5. 读取水面、海床、资源和建设范围。在拟建平台范围及边缘布置固定地形采样点，保存施工前基线；同时为接驳、船舶转弯和后续扩区留出空间。

玩家手动延长码头、拆除或移动平台、修改航道之后，重新勘察；旧端点、候选及净空结论失效。

## 3. 主体与码头

需要新建主体时，先完成陆侧道路与必要服务，使用实时岸线选址候选进入原生预览。需道路的建筑必须回读有效且兼容的 `Game.Buildings.Building.m_RoadEdge`，不能以视觉贴路代替道路绑定。

码头延长使用 `list_pier_pathway_prefabs`、`list_pier_pathways` 和 `preview_pier_pathway`，不是 `preview_waterway`。从实时水侧永久控制节点施工；预览通过后提交，待操作 `completed` 再回读延长边链、长度和末端。随后重新检查两侧航道及泊位是否实际存在，不因码头完成而假定航道同步连通。

## 4. 水上平台放置与高度

1. 查询主体允许的升级，使用 `plan_special_building_site`，传入主体 `owner_building_id` 和 `mode=floating` 获取候选。
2. 检查候选的平台占地、自带航道、原生升级范围、水深和前述避让走廊。四角有水只是基础条件，不替代完整净空检查。
3. 将候选的三维位置、朝向及 owner 原样用于 `preview_building_upgrade`，选择 `placement_mode=floating`，不附加不相关道路目标，不自行改写平台高度。
4. 仅在 `preview_ready`、`can_commit=true`、错误为空且费用可接受时提交。等待原操作 `completed`，按返回的永久实体重新读取平台、owner、自带网络与停靠点。
5. 对照施工前固定采样点检查海床；运行模拟后再次检查，确认没有因错误高程产生新增陆地。

原生浮动高度由实时水面、prefab 的 `m_PlacementOffset.y` 和地形参考点计算。历史实测顺应塔偏移 9.8 米、半潜式偏移 14.7 米，不能互相套用或写成统一常量。带 `RoadSide` 标志时，地形参考点可能位于地块前缘；`ControlPoint.m_Elevation` 必须保留平台与该参考地形的高度差。预览和永久对象均需核对高度及 Elevation。

出现 `FLOATING_ELEVATION_MISMATCH` 时停止，不以抬高海床、填地或反复调整绝对高度绕过。新版本防止错误填地，不会自动恢复旧版已经改变的地形；旧地形修复需要独立勘察与明确范围。

## 5. 石油管道连接

按设施实际连接需求决定是否铺设管道，不把管道和油轮线路视为彼此替代。顺应塔至码头的管道已有实测先例；其他资产仍需从实时兼容端口判断。

1. 发现平台与码头的资源端口、兼容网络 prefab 和 `node_id`，确认两端属于同一兼容产业主体。
2. 使用这些永久端口进行资源管网原生预览，默认省略 `elevation_m`，也不手填绝对高度。管道由游戏处理合法高程和 `LocalConnect` 吸附。
3. 核对 `resource_owner_id`、原生错误、费用及影响，提交后查询原操作。
4. 永久回读同时验证管道归属、主体 `SubNet` 登记，以及 `ConnectedEdge` / `ConnectedNode` 资源图能到达两端请求端口。端口可能通过本地连接接入，不要求与管道端点完全共用一个节点；坐标重合也不能证明连通。
5. 再次采样平台及管道附近地形。出现独立断开的端点、抬升海床或 `RESOURCE_CONNECTION_READBACK_FAILED` 时保留现场诊断，不能更换请求 ID 重复施工。

详见[公用管网指南：海上石油管道接驳](../transport/UTILITY-INFRASTRUCTURE-GUIDE.md#海上石油管道接驳)。

## 6. 接驳航道

平台建成后重新读取码头侧与平台侧的永久航道节点。依据当前船型要求选择兼容航道；不能因为 Boatway 较窄就把它用于要求大型船舶的油轮线路。

使用 `preview_waterway`，在 `points` 中传入实际 `node_id`，曲线使用 `curves`。高度由实时水面计算，不设置管道式的埋深参数。接头切线须连续，按完整航道宽度检查水深和净空。曲率、单段长度和费用以实时工具及原生预览为准，不照搬历史曲线。

预览通过后使用独立且稳定的提交请求 ID、原 `operation_id` 和明确 `max_cost` 提交。仅 `completed` 表示施工完成；再用 `get_waterway` 回读所有新边，确认与请求的永久节点连通。接入既有边可能产生分割对象，不能因返回数量增加就重复补建。

## 7. 油轮作业线路

油轮作业使用 `Oil Tanker Route` 的 WorkRoute，不使用客运邮轮或普通货运运输线路工具。先发现同一产业主体所属的码头工作泊位和平台 `WorkStop`，再预览线路。

当前已验证调用方式：航点提供停靠点的 `x/z`，**省略 `y`**，由工具吸附到原生停靠点。不得把平台甲板停靠点压到水面。当前实现首次预检发生在停靠点吸附之前，显式传入较高的甲板 `y` 仍可能触发 `WORK_ROUTE_HEIGHT_MISMATCH`；省略高度的吸附流程已通过实机验证。

```json
{
  "owner_building_id": "<当前会话的石油产业主体 ID>",
  "request_id": "<本次稳定请求 ID>",
  "route_prefab": "Oil Tanker Route",
  "waypoints": [
    { "x": "<实际码头泊位 x，传数值>", "z": "<实际码头泊位 z，传数值>" },
    { "x": "<实际平台工作点 x，传数值>", "z": "<实际平台工作点 z，传数值>" }
  ]
}
```

以上是参数模板，不可直接执行。使用 `preview_work_route` 后轮询 `get_work_route_operation`。路线自动闭合，不重复首点作为末点。提交前必须满足：

- `state=preview_ready`、`can_commit=true`，无错误。
- `connection_details.stops_ready=true`，两端均绑定有效原生车道。
- `segments_ready=true`、`path_ready=true`，每个往返航段具有有效路径和非负距离。

`apply_work_route_operation` 必须沿用预览的 `request_id`。待原操作 `completed` 后，调用 `get_work_route` 回读永久线路及路径，再恢复模拟检查 `RouteVehicle`。线路完成、派出油轮、实际靠泊装卸和生产吞吐是不同层次的结果，应分别报告。

## 8. 失败恢复与最终验收

所有写事务串行执行。`TOOL_BUSY` 可先以 normal 推进 200–500 ms 再暂停，让原生工具释放状态；仍忙时请玩家回到默认工具。`USER_CHANGED_TOOL` 时先读取原操作，尊重玩家操作。超时、`failed`、`outcome_unknown` 时停止后续相关写入，查询原操作和永久对象，不换 ID 盲目重提。

最终逐项核验：

| 项目 | 完成证据 |
|---|---|
| 主体与码头 | 正确 owner、必要道路/服务连接、永久码头边链及目标延长长度 |
| 平台 | 永久实体、正确浮动高度与 Elevation、自带网络和停靠点 |
| 避让 | 平台及自带航道未压占码头和既有通航走廊 |
| 地形 | 相同采样点施工前后及模拟运行后对照，无非预期抬升 |
| 管道（需要时） | 正确归属、SubNet 登记、资源连接图到达两个端口 |
| 接驳航道 | 永久边与两端节点连通，水深、曲率及净空通过 |
| 油轮线路 | 永久 WorkRoute、泊位车道绑定、全部往返路径就绪 |
| 运营 | 实际车辆数量；靠泊、装卸及产量未观察到时明确说明 |

没有待处理预览且用户未要求暂停时，恢复原模拟速度。规划展示遵循当前局部范围；已有 MCP App 卡片时，不重复打开规划图网页。

- 平台附近 9 个固定地形采样点前后无变化。此采样结论不等于全区域地形的逐点证明。
